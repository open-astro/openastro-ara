### Added
- **The Guiding Assistant from Ara (#1364).** The Guide camera dialog's new assistant button (also under Setup → Smart Focus → Guide camera) runs PHD2's Guiding Assistant without the guider's page: pick one, two, three or five minutes and whether to measure Dec backlash, press Start with a star selected and the mount calibrated, and watch the drift, RMS, seeing and polar-alignment figures fill in. When it finishes, the suggested guide exposure, RA/Dec minimum move, Dec backlash compensation (and, for a mount that cannot compensate, a Dec guide mode or algorithm) are listed ticked, with PHD2's own notes; **Accept ticked** writes them to the guider's profile. Needs openastro-guider with the headless assistant (#83); an older guider shows "not available". Daemon: `GET/POST /api/v1/equipment/guider/live/assistant*`.
- **The guiding graph has history when you connect mid-run (#1364).** Opening Ara during a guided session draws the guider's last minutes (up to 400 frames) straight away instead of an empty graph.
- **The guider's phase on every screen (#1364).** The guider now reports *Looping*, *Star selected* and *Settling* instead of folding them into "stopped", in the same words on the Live strip, the guider dialog and the Run tab — where a new line under the current step shows e.g. *Guider · Calibrating · North step 7 · 11.9 px*.
- **Every guider setting from Ara (#1364).** Tune Guiding → **More…** (or the Guide camera dialog's settings button) opens **Guider settings**: multi-star, star detection (SNR, HFD, mass change, search region), auto exposure, noise reduction, subframes, RA/Dec algorithms, max pulses, Dec backlash, mount options, dither scale and variable delay. Each row shows the guider's current value until you set your own; what you set is kept in the profile and sent on Apply while guiding continues (multi-star on the next guider connect).
- **Guider calibration in Ara (#1364).** The Guide camera dialog shows the calibration beside the picture: PHD2's step plot (RA blue, Dec red) as it runs, the stored result (axis angles, rates, orthogonality, declination) and a verdict — Good, Check (axes off square, or one axis barely moved) or Redo — with the reason. Clear calibration makes the next guide start calibrate again.
- **Guide camera in Ara (#1364).** Live tab → guiding strip → camera icon opens the guider's own picture with the locked star (cross and search box), the other stars it found, the guide star's SNR and mass while guiding, and whether multi-star is on. Tap a star to guide on it; Loop, Stop and Deselect are the guider's buttons. No more opening the guider's web page to pick a star. Daemon: `GET/POST /api/v1/equipment/guider/live*`.
- **"Pause the running sequence" on a critically low disk (#1185).** The `OnDiskSpaceCritical` policy gains `pause` beside `warn` and `abort`: the run suspends at its next step and new frames are refused until you free space and resume. Settings → Unattended running → When to stop lists it.
- **Calibration frames over REST (#1177).** `POST /api/v1/equipment/camera/exposure` takes an optional `image_type` — `LIGHT` (default), `DARK`, `BIAS`, `FLAT` or `DARKFLAT`, any case. It sets the FITS `IMAGETYP`, files the frame under that type in the catalog, and takes darks and biases with the shutter closed. Anything else is a 422.
- **Stats → Pi performance (#1175, §66.7).** A new section shows what the server's computer is doing: uptime, memory in use and managed heap, CPU share since the last read, full garbage collections and total pause, threads (busy and queued), connected clients, the 1-minute load, and the OS/architecture/.NET line. Behind it, `GET /api/v1/server/internal-state` samples the runtime on read — nothing runs while nobody looks. The §66.10 latency budget is now a recorded test (`/healthz`, the new route) that fails only with `OPENASTROARA_PERF_GATE=1`.
- **Dec minimum move (#1156).** The guider's minimum move is per axis now: `minimum_move` stays the RA dead band and `dec_minimum_move` is Dec's, each pushed as its own `set_algo_param minMove`. Settings → Equipment → Guider and the Tune guiding dialog show both rows. A profile from before the split has no Dec value and keeps guiding as it did (Dec follows RA until you set it).
- **Guider profile lifecycle follows the ARA profile (#1156).** Duplicating a profile clones its guider twin (`create_profile` + `copy_from`, not selected), so the copy starts calibrated; renaming a profile renames the twin (`rename_profile`, releasing and reconnecting the guider's equipment only when the twin is the selected one). Identically-named profiles keep sharing one twin. Best-effort like the delete hook: no guider connected → a log line, the next connect creates a blank twin.
- **Terminal status behind the guider 202s (#1156).** Start, Stop and Dither over REST end in one `guider.operation_complete` WS event `{ operation_id, operation, ok, error? }`; a dither — REST or sequencer-driven — also publishes `guider.dither_complete` `{ ok, operation_id?, error? }` with the settle verdict, so a refused dither or a settle failure no longer looks like a success.
- **The rest of the command palette (#1170).** ⌘K now carries equipment operations — park and unpark the mount, find its home, start or stop tracking, switch the camera cooler off — through the same controls the equipment chips use (a device that is not connected answers with a sentence); every sequence template the rig offers as "New sequence from template: …" (creates and opens a run named after the template and the date); and every Tonight's Sky row as "Go to …", which centres the planetarium on it. Templates and targets appear as soon as they load while the palette is open.
- **Run shortcuts and the planner in ⌘K (#1154).** The command palette lists "Run or resume the sequence (⌘R)", "Pause or resume the sequence (Space)" and "Plan tonight…", so the Run tab's keys are discoverable and act from anywhere through the same pre-flight and resume paths as the buttons. The Run tab's empty-state **Plan tonight** button now opens the session planner directly instead of only switching to the Planning tab.
- **Dew formation advisory (#1158, §42.2 row 18).** When the weather station reads humidity at or above 95 % with the air within 1 °C of its dew point, and the recent light frames' HFR has drifted up by 15 % or more (halos forming), Ara opens the `dew_formation` diagnostic — which already makes autofocus wait — and posts one warning per episode ("Dew formation suspected: … Wipe the optics or switch on the dew heaters"). Nothing is parked or aborted; the diagnostic clears itself when the pattern breaks. Rigs without a weather station are unaffected.
- **Verify Position after a Stop Mount (#1159, §57.4).** The post-stop modal gains "Verify Position — show me an image": `POST /api/v1/platesolve/verify-position` takes one quick snapshot (2 s by default, never catalogued), plate-solves it with the mount's reported position as the hint, and answers with three positions side by side — where the image solved, where the mount says it is, and where the last slew was aimed — with the offsets in arcminutes, so you can confirm the mount is somewhere sane before resuming, skipping or ending. It only looks: no sync, no slew. A failed solve keeps the mount's figures and says why; no camera (409) or an unconfigured solver (422) is a sentence in the modal.
- **OSC frames render as luminance; star detection can draw its stars (#1147, §2105).** A Bayered frame whose metadata names a Bayer mosaic (RGGB/BGGR/GBRG/GRBG) now renders its display buffer from the debayered luminance instead of the grey CFA checkerboard; a Bayered frame with no usable pattern still shows the raw mosaic rather than guessing. `DetectStars(annotateImage: true)` draws a ring around each detected star on the display buffer (the plain render is kept beside it) through a headless circle annotator, and the frame loader hands the solver's image data a real star detector and that annotator instead of nulls. RAW/DSLR decode (libraw) and TIFF save remain the pending stubs.
- **Optimal Sub calculator (#1140, NEXTGEN §5).** A calculator icon in the Tonight's Sky header opens a scratch pad over the same maths the planner uses: every input (read noise, full well, e⁻/ADU, QE, aperture, focal length, reducer, pixel size, filter kind and passband, sky brightness, the noise-tolerance knob, the fitted sky-model k) is editable and the Glover floor, saturation ceiling, limiting bound, sky flux and pixel scale recompute as you type; add a target's surface brightness and peak altitude and the Integration Budget tiers appear with their audit lines. It opens seeded from the profile and the rig's fitted k for the first filter's kind; picking another kind swaps in its passband and k. Nothing writes back to the profile; an impossible input is a sentence naming it.
- **The planner uses your sky-model calibration (#1140 P2, stage 3).** A filter kind that passed the calibration gate now scales the planner's modelled photon flux by its k — target and sky alike, since the factor stands for transmission and QE-curve losses the spec sheet misses — so Tonight's Sky's hours scale by 1/k, and the plan dialog's and the sub advisor's sub length follow the real sky rate (a dimmer measured sky moves the Glover floor out). Each row's budget popover names the k it used ("k 0.82 from your frames") or says "not fitted — spec-sheet model". Kinds that did not pass, and rigs that never recalibrated, are unchanged.
- **Sky model calibration (#1140 P2, stage 2).** `POST /api/v1/planning/sky-model/recalibrate` fits, per filter kind and binning, the one factor k that scales the planner's spec-sheet sky flux to what the rig's own frames measured: the library's recent light frames' 5th-percentile background regressed against exposure (two or more exposure lengths give the camera's pedestal with no bias frame; a single length is pinned by a bias frame or reported as unfittable, never guessed). Each kind carries k, the scatter, the pedestal, the measured and modelled rates and the frame count, and passes the Phase-V gate only with k in 0.4–1.5 and scatter under 30 % over at least three frames; a failed kind keeps its figures and says why (one exposure length, no e⁻/ADU on the profile, k outside the band…). The record is stored on the profile (`GET /api/v1/planning/sky-model`, `DELETE` clears; stripped from a shared profile) and shown on Settings → Imaging → Defaults under "Sky model calibration" with a Recalibrate button. Nothing is applied to the planner's hours yet — that is the next stage.
- **Every frame records its sky background (#1140 P2, stage 1).** Every captured frame — lights, darks, flats and bias alike, and apart from the star analysis, so a starless or cloudy light or one the analysis queue had to drop is measured all the same — now gets its 5th-percentile and median ADU stored with the binning at capture on the catalog row; a frame captured before this build or found by the scan is back-filled the first time its histogram is read, whether or not that histogram was already cached. `GET /api/v1/frames` and `GET /api/v1/frames/{id}` carry `background_adu`, `median_adu`, `bin` (and the list carries `gain`). The percentile, not the median, is what the Integration Budget's calibration will fit against: a frame-filling nebula lifts the median but not the darkest 5 %.
- **The pre-sleep checklist (#1138, §58.14).** `GET /api/v1/preflight/today` runs a one-shot self-test and grades it: the mount and camera connected (other selected devices and unresolved faults warn), free space against the profile's storage thresholds, the plate solver binary and star database present (a presence check, not a test solve — the card says so), the cooler within 1 °C of its setpoint, the mount tracking and unparked, the running sequence, when the active target crosses the flip point tonight and its altitude then against the site's soft warning and hard floor, the unattended hours (the explicit window or astronomical darkness) and the alarm device (the connected client, with whether its alarm sound is on). Anything the daemon cannot read grades *unknown*, never a silent ok. The client shows it once per night as the bedtime card when a sequence is running after dark ("All good — let me go to bed" / "Adjust"), remembers the answer per night on this device, and keeps it on Setup → Before you sleep with a Refresh.
- **The session planner knows what you have already banked (#1140, P5).** What-if-run now reads the library's per-target integration: a slice that completes a target's full-structure tier tonight earns a bonus (scaled by how much of the remaining need it covers), a target whose tier is already complete keeps only a fraction of its hours value so a fresh object takes the slot, and the plan's notes say which it was ("this slice completes its full-structure tier" / "tier already complete — diminishing returns"). Without a budget or anything banked the plan is unchanged.
- **Unguided ladder with a short prior (#1264).** A spec-sheet or stored prior short enough that only one rung fit under twice it (a 5 s floor gave a single 10 s rung) made every probe inconclusive; the prior itself now opens the ladder (`[5, 10]`), so a clean frame earns the longer figure. The mount's spec sheet feeds the prior only while the mount is connected.
- **Imaging → Unguided is editable (#1264).** The guard's two eccentricity bars and its step-down / step-up streaks, the Tracking Probe's ladder, Center After Drift's threshold and solve cadence, and the tolerance basis the spec-sheet prior is built on are a profile section (`GET`/`PUT /api/v1/profile/unguided`) edited on Settings → Imaging → Unguided like any other panel; the guard can be switched off. Every default is the shipped behaviour, so existing profiles and runs are unchanged. Guided rigs are untouched.
- **The mount's spec sheet seeds the unguided prior (#1264 stage 1).** When the telescope driver publishes AlpacaBridge's `openastro:specs` sheet (periodic error, worm period, encoders, PEC, mount type), the daemon reads it on connect and shows it on the mount's readiness card and under Imaging → Unguided ("No spec sheet for this mount" otherwise). Before anything is measured, the Tracking Probe starts from the prior the sheet implies for your pixel scale, seeing and polar alignment, and the sub advisor shows the daemon's figure as "Unguided: about N s (from the mount's spec sheet (manufacturer); the first run measures it) — the run uses this lower figure until it has measured.". A measured ceiling still beats the sheet; no bridge build ships sheets yet, so today every rig reads "no spec sheet".
- **Collimation health, as a picture (#1139, §59.10).** After an autofocus sweep on an obstructed scope the Smart Focus card now draws the daemon's verdict: the donut with the central-obstruction shadow displaced where it was measured (exaggerated so a slight shift is visible), the headline (looks good / slight / significant — collimate before continuing), the offset as a percent of the donut diameter with its clock position in the image, how many donut stars fed it, and what that usually means for your optical design. The picture is in the image frame as displayed — the eyepiece view needs your train's mirror flips, and the caption says so. A new run clears it; refractors and in-focus fields get no verdict.
- **The morning card (#1138, §58.13).** When the client reconnects and finds a run that ended, failed, was stopped or was parked awaiting you while nobody was watching, one card says what happened and when ("M81 night (M81) paused and is waiting for you; the rig was dealt with at 03:30" — the time comes from the daemon's own record for that sequence, never from an unrelated morning warning), how many frames landed, and what the daemon did about it — the warnings and alarms it posted during the run, the unattended-shutdown record among them — with Review details (the notification centre), Open the run, and Got it. Shown once per run and outcome on this device (a dismissed "paused" card never hides the same run's later failure); a run you watched end live never gets a card; anything older than 36 hours is history, not a card.
- **Integration budget: auditable hours, a planning knob and a tier standing (#1140).** Tonight's Sky's row details now show how "Hours needed" was computed (surface brightness, tonight's sky with the moon's share, passband, airmass, the sky and target fluxes, the SNR goals); each row reads its banked hours against the full-structure tier as a standing ("2.8 h to go — finishes tonight", "needs another night", or a *Tier complete — diminishing returns* chip that steers the night toward something new); and Settings → Imaging → Defaults gains the Glover noise-tolerance knob (5 % classic, 1–20 %, kept on this device) that Tonight's Sky, the plan dialog and the sequence editor's sub advisor all read for the sub length (the budget's hours do not depend on it). The M42 / North America Nebula / IFN golden cases from the design doc are pinned as tests.
- **Mosaics are projects now (#1146, §47).** Framing a mosaic in the planetarium and adding it to the sequence also records the project on the daemon: the grid, overlap, angle, every panel's centre and how many light frames a panel owes. Per-panel progress is read from the frame catalog itself, so "panels 1–3 done, 4–6 owed" is true after a restart, after a second night on the same project, and after frames are deleted. The Library opens with a Mosaics section: one row per project with the panels-done count and a dot per panel.
- **The setup wizard works without the rig (#1137, §2).** Saving a profile with no daemon in reach (or when the connection drops mid-save) keeps the profile on this device and applies it on the next connect (to the first rig that connects, or to the same rig when the save had already started there), through the same save the connected wizard uses; a note says what was applied. A rig that rejects the replay gets no retries: the draft is discarded and the note says to finish the profile from Setup. Only the profile itself is replayed: connecting the equipment, pushing the guider profile and building guider darks still happen from Setup once you are at the rig. Offline planning now honours the custom horizon you drew (it is part of the cached profile), and switching to a different server mid-session sends you back through the launch flow instead of planning against the old rig's gear.
- **Center After Drift is back (#1195).** NINA's trigger was dropped in the .NET conversion, so imported plans loaded it as an unknown trigger. It now runs on the daemon: every Nth saved light is plate-solved from disk (no extra exposure), and when the field has drifted more than the threshold (10′ by default) from the target the next light is preceded by a re-centre through the same solve → sync → re-slew loop the flip uses. A frame that does not solve leaves the trigger quiet. On a rig without a guider the run builder adds it to every imaging loop, aimed at the target; it is in the sequence editor's trigger picker too.
- **Meridian-flip recovery policies and an explicit unattended window (#1138, §58.4/§58.6/§58.10).** The safety policies gain `meridian_refocus` (only if the focuser temperature drifted since the session's last autofocus — the default, with a 2 °C threshold — or always, or never), `meridian_guider_recal` (restore the guider's calibration with the reverse-Dec flag, run a full recalibration, or do not resume guiding) and an optional site-local `unattended_window_start`/`end` (HH:mm, wrapping past midnight) that replaces the sun-computed darkness window for "louder alerts overnight". The flip now re-focuses after the re-centre, as the spec orders it, and the pre-flip flight check requires the focuser and guider only when the policies will use them. Settings → Unattended running carries the three new controls with help.
- **Smart Focus measures the focuser's backlash (#1139, §59.7).** After every calibrating (Classic) autofocus sweep the daemon appends a three-frame backlash probe at best focus: a control shot below best, a straight upward return (a focuser with backlash stops short, and the fitted V-curve says by how many steps), and a compensated return to verify it. The result lands on `focus_calibration` (`backlash_up_steps`, `backlash_verified`) and in the `autofocus.completed` event; Smart Focus then overshoots its one upward bracket shot by the verified backlash so the optics, not just the counter, land where asked. Nothing is asked of the user, and a probe that cannot measure (clouds, best focus at the travel stop) records nothing and leaves focus where the sweep put it.
- **Unguided exposure ceiling: the run measures how long a sub the mount holds (#1264).** On a rig without a guider the run builder now adds a Tracking Probe after focus and before the first imaging loop: a ladder of exposures (10/30/60/120 s, then the planned sub or twice the prior as a final rung, whichever is lower) is measured for star trailing, and every imaging loop is shortened to the ceiling the ladder decided — the longest passing rung, moved halfway toward the first failing one when there is one (60 s passing and 120 s trailing gives 90 s) — with the frame count re-derived so the planned integration holds. An Unguided Exposure Guard on each loop then steps the exposure down a rung after two trailed frames (tagged `trailed`, one notification) and back up after ten round ones. The measurement is stored on the profile as `tracking_calibration` (`GET /api/v1/tracking/calibration`, `POST /api/v1/tracking/recalibrate`) and streamed as `tracking_probe.*` events, and becomes the next run's prior; a result more than 2× off the prior raises a notification. Light frames now record their median star eccentricity in the catalog. Guided rigs are unchanged. The mount's spec-sheet prior arrives with AlpacaBridge #815; the readiness fact, advisor line and Run-tab readout follow in the client.
- **The unguided ceiling reaches the client (#1264).** The mount's readiness card shows the last measured ceiling, the sub advisor prints "Unguided: about N s" next to the sky-limited exposure on a rig without a guider (the run uses the lower), the Run tab shows the Tracking Probe rung by rung and the ceiling it chose, and Settings → Imaging → Unguided shows the record with its ladder and a Recalibrate button. The ladder and pass rules stay fixed on the daemon; the spec-sheet prior still waits on AlpacaBridge #815.

### Fixed
- **A device whose reads keep failing turns its chip amber instead of staying green.** AlpacaBridge kept answering "connected" for the filter wheel and the camera on 2026-10-16 while every position / state read failed (`EFW_ERROR_REMOVED`, `ASI_ERROR_GENERAL_ERROR`); Ara only noticed at the next filter change or exposure, minutes later. Each device service now watches its essential read (wheel position, camera state, focuser and rotator position): three failed ticks in a row raise a standing `degraded` fault — the chip goes amber with the driver's error and the fault log gets a row — and the first good read afterwards clears it (so does reconnecting the device yourself). Nothing is paused: the instruction that needs the device still reports its own failure.
- **Home and Park from the client stop guiding first.** The sequencer's Park and Find Home instructions already did; the REST buttons did not, so on 2026-10-16 the guider chased a lost star for nine minutes after a Home. A guider that is not connected is left alone, and a guider that will not stop never blocks the move.
- **A lost guide star pauses the run, and the run resumes on its own when the star is back.** When the guider reports its star lost for longer than 30 s (cloud, dew, a knock), the `on_guider_lost` policy runs — pause by default — with a "Guide star lost — sequence paused" notice; the first guide step afterwards resumes exactly the runs it paused ("Guide star back — sequence resumed"). A star that returns within the grace does nothing, the watch re-arms for the next cloud, and a star lost while the guider was only looping is ignored. If the weather turns unsafe before the star is back, the safety engine takes the pause over and its auto-resume covers the run when the sky clears. Before this, nothing in Ara reacted to a lost star: the run carried on unguided.
- **A frame no longer starts on a star that has not settled.** When a dither fails to settle, the run now dithers once more; if that fails too, or the guider refused the dither because it was not guiding, the run pauses awaiting you ("Dither failed … press Resume to dither again") instead of exposing on a swinging star — on 2026-10-16 two settle timeouts were followed by two trailed frames. A rig with no guider connected behaves as before; a rig whose guider is connected but deliberately not guiding (no Start Guiding in the plan) now pauses at its first dither instead of imaging on — take the Dither out of such a plan. A guider that disconnects while the run is parked keeps the run parked on Resume ("the guider is not connected") until it is back. The guider's successful settle reports are no longer logged as `PHD2 error:` with an empty message (46 fake errors that night, each escalated to a warning).
- **A separate guide scope no longer hands the guider the imaging rotator.** The guider rotates its calibration by every move of the rotator it is given, on the assumption that the guide camera turns with it — true for an off-axis guider, false for a guide scope. On the night of 2026-10-16 the CM4 rig's guider profile named the imaging CAA, so a 49° Center and Rotate turned a good calibration into dither spirals and trailed frames until guiding was stopped. The guider's Rotator picker (Settings → Equipment → Guider and the setup wizard) is now offered only when the guide setup is *Off-axis guider*; a guide-scope profile drops any rotator it still carries (on load and on save) and tells the guider "None" at every connect, so a rotator stored in the guider itself stops steering calibration too. The help text says why. **If your guide camera really does ride behind the imaging rotator (an OAG), set Guide setup to *Off-axis guider* after upgrading** — the setting defaults to guide scope, so an OAG profile that never chose it will stop sending the rotator until it does.
- **Autofocus on a colour camera through a narrowband filter.** Stars are now detected after the four Bayer colours are brought to one background level: on an ASI533MC Pro with an L-eNhance filter the raw mosaic's uneven colours raised the detection threshold tenfold, so probes saw 26 stars where the frame held about 240, curves were noise and Smart Focus could never run. The probe preview is debayered too (also in Bahtinov focus and rotation assist).
- **Autofocus no longer settles out of focus.** A curve that explains less than R² 0.7 is refused and the focuser returns to the start, probes whose binned frame says far from focus while full resolution reads as sharp as focus are dropped (the false plateau that drew a run 900 steps out), and the edge re-centre follows the probes the fit used.
- **Automatic step size recovers on its own.** When a stored curve width makes the sweep too wide and the fit fails, the run re-sweeps at the step its own probes measure, and a successful run stores the narrower of the measured and fitted widths.
- **The coarse search keeps a start that is already in focus** when the binned frame loses the sharp stars there, including next to the travel stop.
- **Polar alignment arrows south of the equator.** The azimuth arrow and the bullseye are drawn as seen facing the pole you align on: facing the south pole east is on the left, so "Move east" no longer comes with an arrow to the right. The words were already right.
- **Polar alignment unparks a parked mount** before its first slew instead of failing with "the RA seed slew was rejected by the mount"; a mount that will not unpark stops the run at once as `mount_parked` with a message saying so.
- **Smart Focus enters its + bracket from above**, so focuser backlash can no longer shorten it into a false "no clear rise" (replaces the §59.7 upward compensation, which depended on a backlash the probe cannot measure at the V's bottom).
- **No storage disk, no run (#1374).** Starting a run with the storage drive missing (or the disk critically full under an abort/pause policy) is refused with a **No storage disk** dialog and an Open Storage button, instead of failing every frame. A drive that falls off mid-run pauses the run until you plug it back in and press Resume, and a frame that was never taken no longer triggers a dither or counts toward autofocus — the night it happened, the guider sat "settling" for half an hour with nothing saved.
- **Guide camera gain is Ara's, not the guider's 95 %.** A fresh guider runs its camera at 95 % gain, which put a ZWO ASI290MM at 570 of 600: guide frames were pure read noise and guide focus found no stars. The profile now holds a guide camera gain (`phd2.guide_camera_gain`, percent of the camera's range, default 50 %) that Ara sends with the guider's `set_camera_gain` once the camera is connected — on connect, on a profile push and on Tune Guiding → Apply — and Tune Guiding gets a **Guide camera gain (%)** row. Existing profiles take 50 %.
- **Selecting a profile now brings its unguided-imaging settings (#1264).** Profile select and clone skipped the Imaging → Unguided section, so the previous rig's probe ladder and guard settings stayed active.
- **Storage helper follow-ups (#1248).** `configure-storage.sh` no longer dies silently when its `/run` lock file cannot be opened (read-only `/run`): it warns and falls back to one unlocked fstab rebuild. The boot sweep of the storage exchange directory leaves files younger than five minutes alone, so a daemon restart during a long format no longer takes the result a still-running helper unit is about to write. The helper's `FSTAB`/`FSTAB_LOCK` are bench-overridable and a `--fstab-entry` mode runs only the locked rebuild, so six concurrent rebuilds against a scratch fstab are now a repo test (`scripts/tests/test_configure_storage_fstab.py`) instead of a manual VM run; the composition-root test proves the boot sweep runs at startup; the playbook's §29 exit-code table matches the script.
- **Run ETA honesty (#1155).** An instruction now declares that its duration estimate is a real figure (`IEstimatesOwnDuration`: a zero means zero seconds) instead of being on a hand-kept list — so a readout-mode or USB-limit change costs nothing rather than the 15 s placeholder, and a new instruction with a duration model cannot fall out of the list. A running instruction is charged only its unspent part (a 300 s exposure 250 s in counts 50 s). `instructions_total` no longer counts disabled instructions, matching the time estimate. A live-edit move refreshes the estimate even though no count changed. The Run header's remaining-time figure keeps the daemon's estimate at a loop-pass boundary instead of blanking to 0 when every leaf of the pass is done (the progress bar still reads the leaf count). A time-of-day wait is no longer credited twice for the time already spent. A time condition's remaining-time read no longer rewrites its rollover time as a side effect.
- **Every storage view agrees on whether the frames disk is really there (#1231).** After a restart with the disk unplugged, the Storage panel could still show the SD-card partition as the ARA store and report the SD card's free space as the store's, while captures were (rightly) refused. The device list and the disk-space numbers now ask the same question the capture gate asks. That question is answered from the kernel's mount table with device numbers: a deliberate `mount --bind` of another folder onto the store path now counts as a store, a disk unplugged under a still-standing mount is reported as ejected, and a btrfs subvolume is a store.
- **A wrong `OPENASTROARA_CFITSIO_PATH` no longer breaks every FITS write (#1214).** A path that loads but is not CFITSIO (say `libm.so.6`) used to be cached and win over the system's `libcfitsio.so.10`, so every capture failed with a missing-entry-point error. Each candidate is now checked for a known CFITSIO export before it is accepted; the boot log names the rejected one and the daemon falls through to the real library. CI's arm64 end-to-end run now also asserts the boot probe logged.
- **Southern targets were slewed to the wrong declination (#1195).** The client wrote a negative declination as unsigned degrees plus a sign flag, which the daemon (NINA's rule) read as degrees minus the minutes: −5°24′ became −4.6°, so every plan, custom-coordinate entry and horizon condition south of the equator was off by twice its arc-minutes. The client now writes NINA's signed form and reads both. Runs saved by an earlier client keep the old shape until they are rebuilt from the Plan tab; a stored body south of the equator is worth re-creating.
- **Sequence cooling steps survive a bad read and a slow TEC (#1210).** A single failed cooler read during Warm Camera no longer skips the warm ramp and switches a −20 °C TEC straight off; the step falls back to the daemon's cached cooler state. Cool Camera only gives up after 2 minutes when the cooler has reported full power the whole time (one 100 % sample while regulating used to shorten a legitimate descent); a TEC idling at 0 % during a cool is treated as headroom. A cool written in one step (the dark-library path) no longer raises a cooling-drift fault while the sensor is still visibly descending. The ramp syncs the Thermal Switch fan once a minute instead of every 15 s, and a second cooling step while one is running is refused rather than fighting it for the set-point.

- **The guide camera is pinned by identity, not by Alpaca device number (#1308).** AlpacaBridge numbers ZWO cameras in SDK enumeration order, which can swap across a restart, so a guide camera saved as `Alpaca Camera [host:port/1]` could open the imaging camera after a reboot. Picking a guide camera now stores its Alpaca UniqueID too. Before each Apply the daemon re-reads the server's device list: a camera that moved to another number or vanished is refused with the new location, and so is a guide camera that is the main imaging camera. Profiles saved before this get the main-camera check only until the camera is picked again. `GET /equipment/guider/alpacadevicenames` adds `unique_ids`; the phd2 profile adds `guider_camera_alpaca_unique_id`.

- **Disconnecting equipment by hand ends its recovery (#1307).** When a mount or camera dropped and the daemon was still trying to bring it back, disconnecting it from the client or the API did not stop the recovery: a later attempt reconnected the mount, sent AbortSlew, and the fault log said it was "re-adopted". Recovery now checks for a deliberate disconnect before every reconnect attempt and before the give-up park, stops with a "released" record and a notification, and leaves paused sequence runs paused. The Faults panel shows such rows as "released — disconnected by hand".

- **Settings → Guider pickers save a device, not a bare driver name (#1306).** The guide camera and mount lists used to offer only the daemon's generic "Alpaca Camera" / "Alpaca Mount"; saved as-is with no Alpaca host or port, the push never told the guider which server to use and it sat on localhost:0 with nothing connected. The pickers now list every real device on the stored server and on any server Discover Alpaca finds as `Name (host:port/N)`, picking a camera fills the Alpaca host and port, and Apply refuses a bare selection with the reason. The daemon refuses the same push with a 422 instead of leaving the guider disconnected. A profile that already held a bare `Alpaca …` selection with no Alpaca host and port needs a re-pick once, even if the guider still had a server configured on its own side.
