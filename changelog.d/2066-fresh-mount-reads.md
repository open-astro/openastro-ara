### Breaking changes
- **Polar Align refuses a mount that reads a Dec past the pole** (Polar Align, #2066): a mount that reports a declination beyond ±90° (some do after a sync, such as an iOptron HAE29C reading 90.9°) used to have its reading folded to the same sky point and turned from it. Its pier side is ambiguous there, so a start is now refused with the new Refusal cause `polar-align-pose-ambiguous`, and a run that reads it fails with `pose_ambiguous`, before anything moves. **After upgrading:** point the tube 2–5° from the pole, counterweights down, with the hand controller (or send the mount Home), then start Polar Align.
- **`polar_align.error` reports `pointing_unknown` instead of `mount_fault`** (Polar Align, #2066): a run that had no fresh reading of the mount used to fail as `mount_fault`; that reason is retired. A start with no fresh reading is now the Refusal `polar-align-pointing-unknown` (it was a 409 with no cause). A mount that reconnects during a run now ends it, the adjust loop included. **After upgrading:** a script that matched `mount_fault` matches `pointing_unknown`; after a reconnect, start Polar Align again.

### Fixed (polar alignment)
- **Polar Align moves only from a fresh reading of the mount** (Polar Align, #2066): every turn starts, runs and stops on where the mount says it points right now, through one seam to the telescope service, never on the app's last known position. A reading that is missing, the blank (0, 0) position, more than 2 s old, or from before the mount reconnected stops the motor and ends the run before the next motor command; a start with such a reading is refused before the camera is taken. Confirming that the mount stopped no longer counts a missing, blank or stale reading as "still". A park, Home or Emergency Stop that lands with a reconnect is left to finish: Polar Align no longer sends a stop that would cancel it. A pier flip the app's last known state missed now makes the next Polar Align start a new one.
