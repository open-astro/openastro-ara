### Added
- **Stats maintenance in Settings.** Your night → Stats gains "Clear & rebuild stats": wipes the frame catalog (charts + library) and re-ingests from the connected store drive, so after a drive swap the numbers describe exactly what's on this disk. FITS files are never touched; the confirm dialog spells out what is lost. `POST /stats/rebuild-catalog`, excluded during runs/exposures/scans.
- **exFAT is the new-drive default — take the drive with you.** The §29 format flow now offers exFAT (reads natively on Windows and macOS — pull the drive at pack-up, plug it in at home; the field workflow) alongside ext4 (journaled, for rig-resident drives), and an already-working store can be deliberately erased to switch formats. Every fresh format builds the retail-drive layout — GPT, one Microsoft-Basic-Data partition, the whole disk rebuilt from scratch — and labels it **ARA-DISK**. Because exFAT has no journal, the Storage panel gains **Check disk**: a user-triggered fsck (drive briefly offline, seconds to a couple of minutes) that reports clean/repaired — deliberately a button, never a forced scan. **Eject** flushes and unmounts for safe removal ("safe to unplug"; a replug automounts), and plugging or pulling a drive shows in the app within seconds via the new device watcher. `POST /storage/check` + `/storage/eject`; the .deb depends on exfatprogs. Verified end-to-end on hardware: rig-format → capture → eject → read on macOS/Windows.
- **Desktop backups now read like the originals.** The §44 backup mirror reproduces the rig's §29 file naming (`Backups/<host>/2026-08-05/Light/M31_180s_0001.fits`) instead of UUID session/frame folders. Older servers and existing UUID-named backups keep working; every server-provided path segment is sanitized so nothing can write outside the mirror root.
- **Frame Statistics in the Imaging tab.** A NINA-style readout under the rail — Width/Height, exact Mean/SD/Median/MAD from the raw 16-bit pixels, Min/Max with pixel counts (warning-red past 0.1% at the rails), #Stars/HFR when analysis lands, Bit depth/Gain/Offset — served by the new `GET /frames/{id}/histogram` endpoint and cached beside the preview variants.
- **Blank-disk onboarding.** A brand-new drive (no filesystem, no UUID) can now be chosen and formatted from the Storage panel: the client passes its `/dev/` path, the server validates it as an alternate identifier, and an unlabeled drive demands typing ERASE before the erase button arms.
- **§29 storage & filenames** (back-filled, PR #923): choose/mount/reformat a USB drive as the frame store from Settings (fstab-persisted, system disks refused on both the API and the privileged helper); frames are named like a person would (`2026-08-05/Light/M31_180s_0001.fits`) via a template the server expands at capture — imported NINA templates keep working behind Advanced; the FITS header grows the full story (identity, site, optics, sensor temperature, sky & weather, sun & moon — each behind its own switch, with a "See every header" reference showing your live values); `POST /storage/rescan` catalogs frames already on a disk; plus a notification inbox reachable from ⌘K.
- **§45 polar alignment end-to-end** (back-filled, PRs #888–#891): 2-point seed engine, live adjust loop with WS streaming, settings + session log + complete endpoint, and the client bullseye panel.
- **§76 Wizard 2.0** (back-filled, PRs #901–#907): the five-screen setup wizard — equipment readiness, guiding decisions, and a finish that provisions the guider and kicks off darks — replacing the old 18-screen flow.
- **Guider equipment management in Ara** (back-filled, §63.17–.19, PRs #877–#885): camera/mount pickers with Alpaca discovery, apply-to-guider, dark-library management, guider restart, live guiding panel with real-time RMS, and guide-scope-vs-OAG setup type.
- **Setup-stage flow + guider setup wizard** (back-filled, §25/§63.20, PRs #897–#898): capture-fetch for §45, the solver-profile bridge, and guider profile-follow.
- **SQM + sky temperature** (back-filled, PR #913) relayed from the observing-conditions device into the weather panel.
- **Mosaic runs from the framing overlay** (back-filled, PR #912): multi-tile run creation.

### Changed
- **By-object folders are the default.** New setups file frames as `M 31/2026-08-05/Light/…` (a folder per project, nights inside); calibration frames — which belong to the night, not a target — group beside the object folders as `<night>/<type>`. Existing profiles keep their saved scheme.
- **The picture shows in seconds, not a minute.** After a capture the preview renders at readout time (pre-warmed into the §65.4 cache), mono frames decimate before the stretch, the image downloads via raw Alpaca ImageBytes (no 104 MB intermediate), and pixel conversion is a tiled parallel transpose — a 1 s exposure previews in ~5 s on a Pi 4, at full superpixel resolution (4096 px cap, up from 2048).
- **Imaging tab redesigned around the frame.** The viewer owns the full canvas for every sensor aspect; exposure controls compact into a two-column grid at the top of a right rail with Solve, Guiding, Statistics, Diagnostics and Faults below. New frames open fit-to-window; double-click toggles fit ↔ 1:1 pixels at the click point.

### Fixed
- **Exposure/gain/offset/bin edits commit on focus loss.** Typing a value and clicking Take One previously shot with the old value unless Enter was pressed first.
- **Server discovery survives broken in-app multicast** (back-filled, PR #916) by falling back to a subnet sweep.
- **macOS window opens normal-sized** instead of maximized (back-filled, PR #894); guiding tuning moved to a Tune dialog (back-filled, PR #893); PHD2 wording rebranded to OpenAstro Guider throughout (back-filled, PR #900).
- **Reformat confirmation is a real gate again.** The typed label is what the server checks — a stale client record can no longer erase the wrong disk; fstab rewrites are atomic and system-disk detection walks the full parent chain (LVM/md/dm-crypt-safe).
- **Sun/moon FITS headers use the frame's capture instant**, not wall-clock at header-write time.
- **Restart the server from the app.** Support tab gains **Restart now…** (confirmed — it interrupts running work) and **Restart when idle** (waits until nothing is running), so recovering a wedged daemon no longer means finding a laptop and an SSH session at the rig. About now also shows the *server's* build, git sha and platform alongside the app version — the half that actually runs your gear was previously invisible.
