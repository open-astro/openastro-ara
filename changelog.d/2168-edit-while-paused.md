### Fixed

- **A setting changed during a run is used for the rest of it** (sequencer, #2168). Changing Take Exposure's time (or gain, binning, a Switch Filter's filter, a loop's count, a trigger's setting) while the run is going or paused now sticks: the row shows the new value, Save is available, and Save or Resume sends it to the running plan. Frames already taken and the frame in progress keep their old settings; every frame after that uses the new ones, as in NINA. Before, the change was dropped with only a brief message, the editor still showed it, and the run kept the old value. Every Resume button (Sequencer, Simple plan, the "press Resume" message, the stop overlay) sends unsaved changes first, and Run saves unsaved edits before it starts. If an item is added, removed or moved elsewhere meanwhile, each unsaved change stays on its own item. A target's coordinates, a time source, and adding or removing a loop rule or trigger still need the run to finish, and say so.
