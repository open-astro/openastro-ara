### Added
- **§54 — overnight problems can now reach your phone.** Pushover and Telegram push channels are live: fill in both of a channel's fields (Pushover app token + user key; Telegram bot token + chat ID) under Settings → Session → Notifications and warning-or-worse events forward automatically — critical ones ride Pushover's high priority, bypassing your phone's quiet hours. The in-app feed stays the source of truth; a provider outage never delays anything.
- **§29 — captures stop before the disk fills, not after.** With the "abort on critical disk space" policy set, each exposure now checks the save volume's free space before the shutter opens and refuses to start when it's critically low — an exposure that can't be saved is wasted sky time. The disk monitor's 60-second poll used to leave a window a burst of large frames could slip through; the default "warn" policy is unchanged (never blocks).
- **§58.10 — nighttime problems ring louder.** While your site sits in astronomical darkness, equipment-impacting warnings are automatically raised one severity level (warning→error, error→critical) so the bedside alarm behaviour engages earlier for a sleeping user — each raised message says it was escalated and why. Daytime severities are untouched; a profile toggle turns it off.
- **§58.8 — the first flip on a profile announces itself.** The one failure mode that actually breaks gear is a new profile with a wrong pause value flipping the OTA into the tripod — so the very first meridian flip on a profile now posts a critical alert and waits 60 seconds before proceeding (stop the sequence if you want to check your settings first). Later flips run silently, and changing the optics train re-arms the one-time announce.
- **§58.7 — flip failures reach you in every mode.** A failed meridian flip now posts a Critical notification even without the §58.9 safety layers enabled (it used to halt the sequence silently), and says whether the guider could be restored. Two quieter degraded paths also speak up: a failed best-effort re-center ("imaging continues on an unverified pointing") and a failed post-flip autofocus ("focus may have drifted").
- **Settings → System → About is real.** The app's identity, version (read from the build), license posture (AGPL-3.0 client / MPL-2.0 daemon, forked from N.I.N.A.), a link to the source repo — and the legally required **open-source licenses page** listing every bundled Dart/Flutter package with its full license text, collected automatically at compile time.
- **§10.6 — sequences can drive a specific switch.** The Set Switch Value instruction is now in the sequence editor's palette (new Switch category) and gained a device selector for multi-hub rigs — target port 3 of *that* power box, not whichever hub happens to be first. Existing and NINA-imported sequences keep their behaviour (no device named = the first hub, exactly as before).
- **NEXTGEN §3.1 — "enough stars to stack?" advice.** Supplying a target position to the Optimal Sub calculator now also predicts how many stars each sub can register (from your aperture, seeing, sky and field of view, via the HYG-validated star-count model) and reports the star-detectability floor: when a sub long enough for read noise would still be too star-poor to align, the window says stars — not read noise — set the floor. Tonight's Sky flags starved fields the same way ("~N stars/sub — thin for registration"). Advisory only; nothing gates on it.
- **§60.9 — the library and calibration screens follow a running capture live.** Every catalogued frame now emits the frame.complete event, and the Image Library, calibration coverage badges, and dark-library build progress refresh automatically as frames land — no more pull-to-refresh while a run fills the catalog.
- **§39.10 — export frames for post-processing.** Select frames in the Image Library and Export downloads a tar of their FITS files via the OS save dialog — ready for PixInsight, Siril, or anything else. That completes the bulk bar: rate, tag, move, export, delete are all live.
- **§65.9 — manual stretch sliders in the frame viewer.** Pick the "manual" palette and shape the stretch yourself: black point, midtone, and white point sliders re-render the full-resolution preview as you drag (debounced to keep the daemon happy on LAN).
- **§40.8 — move frames between sessions.** Select frames in the Image Library and file them under a different session (fixing recovered orphans or snapshots that belong with a real run) via a session picker in the bulk bar.
- **§40 — big catalogs page cleanly.** The Image Library and Calibration session lists load beyond the first 200 sessions with a Load-more button instead of silently truncating.
- **§40.5 — tags and full capture settings in the viewer.** The frame viewer now shows the frame's recorded gain, offset, sensor temperature, focus position, and dimensions, plus editable tag chips — add or remove tags without leaving the image.
- **§40.5 — rate frames from the viewer.** A star row under the preview rates the open frame (tap the current rating to clear); the library strips update immediately.
- **§65 — stretched previews in the frame viewer.** Opening a frame now renders a full-resolution server-side stretch (auto STF by default) with a palette picker — linear, log, asinh, sqrt, equalized — while the thumbnail paints instantly as a placeholder.
- **§50 — Stats CSV exports come from your real catalog.** The Stats dashboard's Sessions/Frames CSV buttons now stream the daemon's catalog (sessions as a per-session rollup with light counts and integration), and the last of the built-in demo data is gone.
- **§40 — find frames faster.** The Image Library's header pills are live: narrow every session's frame strip by filter or minimum rating, and search sessions by target name — active filters highlight, and one tap clears them.
- **§40.6 — Resume Target is real.** The Image Library's Resume Target button now builds a ready-to-run sequence for continuing a multi-night project: the exact sequence the session originally ran when it was recorded, otherwise a per-filter capture plan rebuilt from the lights you took (same filters, exposures, gain, focus, and frame counts) — review, add your slew, and run.
- **§40.8 — bulk frame operations.** Select frames in the Image Library and rate them (1-5 stars or clear), add/remove tags, or delete them — with a confirmation that separates "remove from catalog" from "also delete the FITS files from disk".
- **§40 — the Image Library shows your real catalog.** Session cards, frame strips, and capture-time thumbnails now come from the daemon instead of demo data; tapping a frame opens a pinch-zoomable viewer with its recorded metadata, and every session card can generate matching flats directly.
- **§39.10 — a Calibration screen ties it together.** New Calibration entry in the status bar: browse every imaging session with per-filter summaries and flats/darks coverage badges, generate matching flats from a dialog and land directly on the ready-to-run sequence in the Run tab, and manage the dark library — catalogued dark groups plus the matrix build form.
- **§39.8 — the dark library is real.** The calibration dark library now reflects the frames you've actually captured (grouped by exposure, gain, and sensor temperature) instead of fixture data, and "build dark library" generates a ready-to-run sequence — cooling the camera to each set-point and looping the requested dark matrix — that you review and start like any other sequence. Already-covered combinations can be skipped, and build progress tracks real catalog coverage.
- **§39.5 — "Capture Matching Flats" now produces a runnable sequence.** Generating matching flats for a past session saves a ready-to-run flat sequence: for every filter the session used, it switches to that filter, returns the focuser to the focus position those lights were captured at, and shoots the flats with the same gain and offset — so dust-mote shadows and vignetting calibrate out exactly. Preview-only mode still returns just the plan.
- **§25.5.1 — pick your filter for manual captures.** The Imaging tab's exposure controls gain a Filter dropdown (between Bin and Frame type), sourced from your profile's filter-wheel slot labels — every Take One now records the filter you actually used instead of a hardcoded 'L'. (Live View frames are ephemeral and never catalogued, so no filter is recorded there.)
- **§25.5.1 — binning is now a dropdown of the camera's supported modes.** The Imaging tab's Bin control switches from a free numeric field to a dropdown of the symmetric modes the connected camera supports (1x1, 2x2, … via its capability bin range), falling back to 1..8 when no camera is connected and clamping an out-of-range stored bin instead of crashing.
- **A dead link now goes grey instead of sitting on a stale "connected".** Two watchdogs: the WebSocket flips to reconnecting after 45 s with no frame from the daemon (which heartbeats every 30 s to the client holding the control session), so a silent network drop no longer waits minutes for TCP to notice — the Server indicator and every equipment chip, guider included, go offline together; and a device that was connected surfaces a read error after four consecutive failed polls (~60 s) rather than holding its last green reading forever. A momentary blip still flips nothing, and the first good read restores everything.
- **Fill from GPS falls back to the computer's own location.** When no USB GPS dongle fix is available, "Fill from GPS" now falls back to the desktop's own location service (macOS and Windows; a fresh fix and location permission are required), naming the platform in its guidance when it can't — including the honest answer on Linux, which has no system location service to fall back on. The wizard (profile creation) and the Safety → Site panel share one routine, so both behave identically; filled Lat/Long/Elevation/Timezone now refresh in place.
- **You can type a space in the sequence editor's settings fields again.** The Run editor's keyboard shortcuts sat above the whole tab and swallowed the keys they matched even when they chose to do nothing — so with a settings field focused, the space bar never reached it (no spaces in an Annotation note or a container name), ↑/↓ didn't move the caret, and ⌘Z/Ctrl+Z didn't undo your typing. Every tab shortcut now declines the key when it isn't acting on it, so it carries on to whatever has focus; a Space press with a toolbar button focused activates that button instead of double-commanding the rig, and a shortcut that can't run right now (nothing loaded, command in flight) no longer eats the key either.
- **Switch panel errors are now human-readable.** Writing to a switch port (e.g. DewHeater) on a device that isn't connected used to surface the raw `DioException … 409` text; it now shows the server's own message ("switch '…' is not connected") via the friendly-error mapper, so you know to reconnect the device instead of seeing an opaque exception.
- **Night mode (red display) for dark-site observing.** A new Night mode dims the whole UI to red to protect dark adaptation: a toggle in Settings → System → About, a moon button in the top bar (beside the equipment chips), and an `N` hotkey (ignored while you're typing in a field) all flip it, and the choice persists across launches in the app-support prefs file. It renders as a red colour filter over every painted pixel: each pixel's luminance is folded into the red channel and green/blue are zeroed, so nothing that resets dark adaptation gets through while the UI still reads by brightness. The sky map (a native WebView/Stellarium) is covered by injecting a matching red tint into the page, since Flutter overlays can't paint over native views — on macOS/Windows through the embedded webview, on Linux through the native GTK overlay's own channel, re-applied on every page load.
- **Run editor: numeric fields accept digits, '.' and '-' only; the Annotation note grows with its text.** Value fields in the sequence editor reject letters and symbols at the keystroke, allowing exactly what the field's own keyboard implies — digits always, '.' only on a decimal field, '-' only on a signed one (so a stray '.' can't silently void an integer edit). Range-limited fields already had strict formatters; this closes the unbounded ones. The free-text note field is exempt and now wraps to multiple lines, expanding the field as you type.

### Changed
- **§60.9 — BREAKING (wire): sequence run counters renamed `frames_*` → `instructions_*`.** They always counted sequence instructions, not camera exposures; renamed on both the REST run-state and the WebSocket events while the wire has no external consumers (daemon + WILMA ship together). The stream's ordering contract is now documented in `openapi.yaml`: a terminal event may arrive without a preceding `started`, and `sequence.progress` never arrives after the run's terminal event.
- **§60.9 — sequence progress events no longer pile up under fast capture.** A sequence reporting progress at camera-capture rates used to queue one WebSocket publish per tick with nothing bounding the backlog; progress events now coalesce — at most one publish in flight, bursts collapse into a single trailing update carrying the freshest state. Start/pause/complete events are never throttled, and low-rate progress is still delivered instantly.
