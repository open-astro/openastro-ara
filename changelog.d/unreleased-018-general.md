A frame taken while the astrometry library was missing (pointing in the mount's own epoch) stores no pointing. `GET /api/v1/frames/{id}` returns them as `ra_deg`, `dec_deg`, `pixel_scale_arcsec` and `captured_by_ara`.

Frames another program captured are never listed.
- **Sky Album in Simple Mode (#1521, #1594, #1595).** A Sky Album button on the left rail opens the Messier and Caldwell Books. Each card shows a premade picture of its object (in colour once collected, grey until then, a silhouette where no suitable picture exists); its back lists the latest four nights you imaged it with lights, sub length and hours, a totals row, the object's distance and a short fact, and the picture's credit. "Image this target" and "Add more time" close the album on Plan's sheet with the object picked. The collection is kept on the device and merged across every rig it connects to, so deleting frames on a rig never takes a card or a tier away. Picture credits are listed on the About page.
- **Sky Album: new cards since your last visit (#1658).** Cards collected or moved up a tier since the album was last opened sit on their own shelf above the Tonight shelf and turn from grey to colour once (at once under Reduce Motion); a mouse drags both shelves sideways.
- **Live stacking engine (server side, #1169).** While Live View runs, `POST /api/v1/equipment/camera/liveview/stack/start` aligns each new frame to the first one by its stars (shift and rotation) and averages them, rejecting satellite trails and cosmic rays (hot pixels too when the frames are dithered; a hot pixel on a fixed pixel of an undithered stack is kept). `GET .../liveview/stack/frame` returns the stretched stack as a JPEG and `GET .../liveview/stack` its counts. Stacking clears when Live View stops. The EAA panel comes in a later change.
- **Optional magnitude floor for Tonight's Sky (#1176).** Settings → Imaging → Defaults can hide targets fainter than a set magnitude (6-15, 12 when first switched on); targets with no catalogued magnitude stay listed. Off by default.
- **Simple Mode (experimental).** An image-first shell for imagers who want the rig to just work, behind Settings → System → Experimental → Simple Mode (off by default). The latest frame fills the window and the controls float on two rails: Preview, Focus, Polar align, a quick Plan builder with a live queue and scheduled start, and an Autopilot that walks Focus → Polar align → Plan. It meets WCAG 2.2 AA (keyboard, contrast, text up to 2x).
- **The setup wizard asks for the site's Bortle class and an optional SQM reading (#1185).** Both sit under the location fields on the profile step, are range-checked like Settings → Safety → Site (Bortle 1-9, SQM empty or 16-22.5), and start from the current site values on a re-run.
- **⌘, (Ctrl+,) opens Settings.** The platform's standard Settings shortcut, from anywhere in the app.
- **Smart Focus reads a rim-vs-core asymmetry to tell which side of focus a blurred frame is on (#1139).** For each star it compares how bright the rim is with the core: −1 means the light sits in the core with a soft halo, +1 means it sits at the rim, 0 an evenly lit disc. On a rig with spherical aberration the two sides of focus read differently, so the calibration sweep learns which sign means which side, alongside the existing radial skew; a refractor whose sides differ only in this way now gets a real direction instead of a guess. It is not a focus measure (HFR still judges focus) and reads 0 on small in-focus stars. The value is shown for each probe in the V-curve tooltip and logged for each Smart shot.
- **Calibration that matches the lights (#1432).** Capturing calibration for a session picks Flats, Bias and Darks separately, each pre-ticked when the lights still need it. Matching flats turn the rotator and cool the camera back to where the lights were taken, and solve their exposure and panel brightness from two test frames (remembered per filter for next time). Flats carry over between nights while the filter and rotator angle are unchanged. Bias run at the camera's shortest exposure for each gain, offset and binning the lights used; darks run at each exposure and gain, regulated to the lights' temperature. An optional lens-cap pause opens the panel's cover and waits before the bias and darks. Generated flats, darks and bias file next to the lights (`{target}/{night}/Flat`, `Dark`, `Bias`), and the Dark Library lists bias groups.
- **A camera that drops mid-run pauses the run (#1432).** One failed exposure is retried; a second in the same capture parks the run awaiting the user ("check its USB cable and power…") instead of failing every remaining frame, and Resume carries on (a flat set resumes with only the frames it still needs).
- **Copy to another disk.** Storage → *Copy to another disk…* copies the storage drive onto a second drive plugged into the server: everything on it, or folders you tick (a ticked folder takes everything under it). Files already on the other drive with the same size are skipped, so running it again only adds new frames; a different file under the same name is left alone and counted. Nothing is ever deleted or overwritten on either drive. Hidden OS files, in-flight `.tmp` writes and the preview/thumbnail caches (rebuilt on demand) stay behind. Each file is written under a temporary name, flushed and then renamed, so a pulled cable or a cancel never leaves a cut-off frame under its real name. The copy checks for room first, runs in the background (the panel shows its progress; the dialog can be hidden), and unmounts the drive at the end so it is safe to unplug. It refuses to start during a sequence run, and the store can't be changed, checked or ejected while a copy runs. On the wire: `POST /api/v1/storage/copy {target_uuid, folders?}`, `GET /api/v1/storage/copy` for progress, `DELETE` to cancel.
- **A guide star lost for a long time is recovered by plate solve (§42.2).** The star-lost watch pauses the run after 30 s and resumes it when the guider locks on again — right for a passing cloud, but after a long one the mount has drifted on tracking alone, the star comes back outside the guider's search box, the guider never relocks, and the run sat paused all night under a clear sky. Now, 3 min into a loss, Ara asks the guider's own frames whether stars are back (PHD2's `get_star_centroids`, which touches no guider state) once a minute. Clouds still there: ask again. Stars back: stop guiding, re-center the run's target by plate solve, restart guiding on the guider's own star pick and resume the run, with one Info notice ("Guide star lost for 12 min — re-centered, run resumed"; the fault row records `recentered`). A failed solve or restart keeps the run paused, warns once, and tries again after 5, 10, then every 15 min; the recovery never parks. It defers to the safety engine while that holds the rig, hands over once you pause, resume or stop the run yourself, skips the slew when the target has sunk below your horizon limit, and says so once when the daemon has no plate solver. A **Dither** that has to restart guiding after a gap of 3 min or more re-centers the target first too, so the drifted framing is not locked in; a short gap keeps the plain restart. The three re-center paths (safety auto-resume, resume refinement, this one) now share one implementation, so the safety auto-resume now also skips the slew when the target has set below your horizon limit during the pause and says so in its notice (it used to slew regardless).
- **Setup picks the plate-solver star database for your rig (#1136, §36.10).** The equipment step asks for the reducer or Barlow factor (any value: 0.63 for an SCT reducer, 2 for a Barlow; quick picks for the common ones) and shows the effective focal length and the field of view as soon as the camera has reported its sensor. The review screen then lists the ASTAP database each camera needs — the imaging camera and the guide camera, which solves polar-alignment frames; with an OAG the guide camera's field follows the main optics — with its size, and downloads them on the rig after Save (setup stays five screens). The ladder picks the smallest database that covers each field: W08 above 20°, G05 above 6°, D05 from 1° (109 MB, most refractors and lenses), D50 from 0.5°, D80 below that; a field under 0.15° is reported as "cannot plate-solve" instead of a download. D05 and D50 join the Data Manager; databases are never removed when a second profile's rig needs a different one, and a database another profile already fetched shows as already on the rig. `POST /data-manager/solver-recommendation` answers the same question for any optics.
- **Bug reports have a sharing mode (#1185, §54.3/§54.4).** Support → *Send me a bug report* offers *Include everything* (the default), *Coarse GPS only* (the site rounded to whole degrees, ~111 km) and *Redact all sensitive items*. The daemon applies the mode while it builds the bundle, so the ZIP never held what the mode scrubs: in redacted mode the profile's coordinates and elevation are zeroed and its tokens, serial numbers and host-like fields become `[REDACTED]` / `[REDACTED-SN]` / `[REDACTED-HOST]`, and the logs, profile and system info have usernames in paths, private LAN addresses and `.local` / `.lan` hostnames replaced by `[REDACTED-USER]` / `[REDACTED-IP]` / `[REDACTED-HOST]`. Credential shapes (the daemon's token header, bearer tokens, GitHub / Stripe / Slack keys, private-key blocks) are stripped in every mode. `system-info.json` records the mode. On the wire, `POST /bugreport/prepare` takes `{"mode": "full" | "coarse_gps" | "redacted"}` and the preparation reports `sharing_mode`.
- **Support → Logs pages back (#1185, §29.9).** The log list ends in a *Load older* control that fetches the page before the oldest entry shown, with the same level and text filters, until a page comes back short. On the wire, `POST /server/logs/tail` takes an optional `before` cursor (an instant; only entries strictly older are returned, newest-first).
- **Camera status reports more of what the driver knows (#1185, §25.5.5).** The capability record carries the sensor-type name (Monochrome / Color / RGGB …), whether the camera has a mechanical shutter, the driver's discrete gain and offset name lists (DSLR-style "ISO 800" settings; absent when the camera uses its min..max range instead) and the exposure resolution; the runtime record carries the cooler's heat-sink temperature. All optional on the wire, so an older client or daemon pairs unchanged.
- **The plate-solver star databases download from the app (#1136).** Settings → Sky data now lists ASTAP's star databases as Data Manager packages: **D80** (Gaia DR3, 1.3 GB, the database for every rig), **G05** (105 MB, fields wider than ~6°: short lenses) and **W08** (0.5 MB, wider than ~20°: all-sky cameras). The ones the profile's optics call for are marked Recommended, each download is SHA-256 verified, and a package that would not fit on the Pi's volume is refused up front with the size it needs rather than failing at 90%. They install under the profile's solver index path (`/var/lib/astap`), one subdirectory per package; the solver scans those too and points `astap_cli` at the right one per solve, so a database placed there by hand (DEPLOY.md's old step 3) keeps working and wins over a package copy of the same database. The databases are hosted as release assets on `open-astro/sky-data` (the daemon's download client follows a redirect only to `github.com`, `release-assets.githubusercontent.com` or `objects.githubusercontent.com`, over https), and the field-of-view bands now match ASTAP's own auto-selection: G05 above 6°, W08 above 20°. The H17/H18 databases are obsolete upstream and no longer suggested.
- **Polar alignment close-out (#1133).** The bullseye becomes a polar-scope reticle once the error is under 2′ (a 2′ field with 30″ rings and 15″ ticks, so the last arcminute is worked against marks a frame can resolve), and a knob turned the wrong way is named after one frame ("Altitude got worse after that turn — the altitude bolt moves the axis the other way on this mount"), since mounts differ in which way a bolt moves the axis. Polar-align binning is now **auto** by default: the daemon reads the guide camera's frame size and picks the §45.4 tier (every guide camera in use stays 1×1); 1–4 in the profile still override it. A binned frame is now solved at its true scale (the solver was told 1×1 whatever the capture used). The solve-error budget and the 2-point-vs-3-point decision are written down in the playbook, §45.16: the 2-point seed stays, with a 60° seed rotation as the remedy for a jittery mount.
- **Recent and saved targets follow the profile (#1267).** A target typed by coordinates or resolved by name is kept in the profile (`saved_targets`, with its other names and where it came from), so a target prepared at home is on the list at the dark site on any client, not only the device it was typed on. The client keeps a local copy as the offline mirror: with no server the list still works and the changes push on the next connect. The target dialog's recents now show a resolved target's aliases and source.
- **One object, one row (#1267).** The bundled catalogs each listed their own designations, so the North America Nebula sat in Tonight's Sky, search and the Catalogs overlays three times (NGC 7000, Sh2-117, C 20). Rows that are one object are now folded into one: keyed on the cross-identifications the catalogs carry (OpenNGC's Identifiers / NGC / IC / Messier columns, so Arp 1 is NGC 2857 and the North America Nebula answers to LBN 373), on the curated Sharpless twin list (NGC 7000 ↔ Sh2-117), and as a fallback on position (rows from different catalogs, of the same kind, within 30″: vdB 21 sits on NGC 1432). Rows of one catalog are never merged by position, so a galaxy pair stays two objects. A star row never swallows a nebula (OpenNGC types IC 1318 as a star, Sh2-108 stays a nebula row), and OpenNGC's duplicate designations become aliases of their canonical row (NGC 2244 finds the Rosette cluster NGC 2239, and the curated Rosette override now reaches it). The surviving row keeps its id, name and photometry; the others become its aliases: Tonight's Sky shows the catalogue ones under the row ("also Sh2-117, C 020, LBN 373"; survey ids and further common names stay out of the line), search finds the object by any of them, each Catalogs overlay still labels it with its own designation, and a name resolved through Simbad that the bundle already lists lands on the bundled row instead of beside it.
- **Target search by any name, offline first, then Simbad through the daemon (#1267).** Typing a name the planetarium's search box did not know ("AB Cas", "HIP 12235", "V* AB Cas", "Wolf 359", "M 31", "Gliese 244", "alpha CMa") now asks the daemon (`GET /targets/resolve`). Its offline index answers instantly from the sky-data already installed: every identifier HYG carries (HIP, HD, HR, Gliese, Bayer, Flamsteed, proper and variable-star names) and every one OpenNGC carries (Messier, NGC, IC, cross-identifications, common names), whatever the case, spacing, leading zeros or Greek-letter spelling. A miss goes to CDS Sesame (Simbad, then NED and VizieR) from the daemon, bounded at 5 s, and the answer is kept in the daemon's database so a target resolved at home is still there at the dark site. A resolved name opens the target dialog filled in with its main identifier, J2000 position and provenance (source, type, magnitude, other names), ready to frame or add to the plan; an unknown name reports "not found" or "needs internet" instead of spinning. The client has no internet dependency of its own.
- **Gear swaps behind the same Alpaca slot are noticed (#1362).** Every time a device connects, and again before a sequence starts, Ara re-reads the device's Alpaca `UniqueID` from the device's own Alpaca server (on the rig's LAN, no internet) and keeps it in the profile per gear slot (`equipment_identity`, read-only at `GET /profile/equipment-identity`). A first sighting is recorded quietly. A different id in the same slot posts an inbox notice ("Guide camera changed: Uranus-C PRO → QHY5III585M") that lists what to re-check (focal length, guide focal length, filter offsets, backlash), and clears the calibrations that were measured through the old device: a camera swap drops the Smart Focus, unguided-tracking and sky-model calibrations; a focuser swap the Smart Focus one; a mount swap the tracking ceiling and the guider's calibration; a guide-camera swap marks the dark library and defect map invalid and clears the guider's calibration. Driver-reported facts were already the profile's source (sensor geometry and electronics, wheel slot names, guide pixel size); this closes the 2026-10-15 field case where a swapped guide camera kept the old 3.75 µm pixel size because the wizard was never re-run.

### Changed
- Polar Align turns tracking on before its RA turn when the mount is not tracking, turns it back on if it drops before the turn, and puts it back on exit; a mount that will not track fails as `tracking_off` instead of a refused slew (#1611).
- The pull request template has new sections (Thinking Path, Decision records, Verification, Risks, Model Used) and the new `PR body` workflow checks them: a body that skips or leaves empty a section fails `pr-template`, a new test case without a `Falsified by:` line fails `falsified-by`, and a changed decision record that the body does not name fails `decision-records`. A PR that changes a record in `docs/adr/` also needs a collaborator's `ADR authorized <sha>` comment, and the review bot now checks the diff against each record rule in scope (#1692). ADR 0001 moves into the new record shape with the same decision.
- **Simple Mode's Focuser window has coarse and fine knobs (#1662).** Two upright knobs, like a focuser's seen from the side, replace the round dial and the 10 / 100 / 1000 step picker. Roll a knob up to go in and down to go out ("▲ In" / "▼ Out"); a click on Coarse is 1 % of the focuser's travel and on Fine a tenth of that (100 and 10 for a relative focuser), and the focuser moves when you let go. A mouse wheel (one click a notch), a trackpad's two-finger scroll and the Up / Down keys work too. The status pill shows "Focuser · Moving…" while it moves, outside autofocus. The position shows big on the left and Autofocus is a full-width button under the knobs, green to start and red to cancel. The round dial moved to the Rotator window.
- **Simple Mode's Guide mode is now Guider.** The mode holds the guider's settings (exposure, gain, dither) and starts and stops it, so the rail, the mode grid and search read Guider (pt-BR: Guia). Night Setup's step that starts guiding keeps "Guide".
- **A plain clock time waits for its next occurrence (#1576).** Wait For Time and the Time condition in the full UI, set to a plain clock time (not Dusk, Dawn and the like), now target the next time the clock reaches it, so a sequence started after its time waits for the next one: Wait For Time 21:47 started at 00:30 waits until 21:47 that evening, Wait For Time 22:00 started at 22:30 waits until 22:00 the next evening, and a Time condition loop to 21:47 entered at 21:48 runs until 21:47 the next evening (all three used to go straight on). Night-anchored times keep their targets.
- **Simple Mode says Guide Camera, not Guider Camera (#1586).** The guide camera's device window, top-bar tooltip, Settings › Devices row and search section now read Guide Camera, as the Guide panel does; "Guider" stays for the guiding program (the device chip, the status pill). Portuguese already read "Câmera de guiagem". Search's Dither result now reads "Dither · Guide" and opens Guide mode, where Dither is; it used to open the Guide Camera window, which has no Dither.
- **The moon now lowers Tonight's Sky scores (#1176).** A bright moon up near a target cuts its score by up to 20% (10% when your filter set has narrowband filters), fading to nothing 60° away; the reason chip shows the cut, e.g. `moon 25° away, 80% lit (−11%)`.
- **Imaging runs refocus when the temperature changes.** The profile's Settings → Autofocus → *After temp delta* (2 °C unless changed) was stored but never used; a run built from Simple Mode or the Sky Atlas now carries it as an AutofocusAfterTemperatureChange trigger, so a profile that never touched the setting starts refocusing after a 2 °C drift. Set it to 0 to turn it off. Only with a focuser.
- **Simple Mode keeps you in Simple Mode.** Its gear (and ⌘,) opens Simple Mode's own Settings: **Rig** (the rig's figures, name and profile with *Change*, telescope, site, Permanent pier, the Simple Mode switch, language, versions, logs) and **Devices** (Connect / Disconnect / Reconnect). The Camera, Mount, Focuser and Guider dots open a window for that device. Search (and ⌘K) finds sky objects, Simple Mode's settings, modes and imaged targets. *Show all options* is gone; the Simple Mode switch in Settings › Rig is the way back to the full UI. Logs, *Open Storage* and the dots of devices with no window yet still open the full Settings page over Simple Mode.
- **The app reconnects to your last rig and opens on your last profile.** When the scan finds the rig you used last time, the app connects to it on its own and goes straight to imaging on the rig's active profile (the one you last loaded), with no rig tap, no *Continue* and no *Image*. The app keeps the rig's name and its id, not its address, so a rig that moved still matches and two rigs sharing a name aren't mixed up. The rig list still shows for a rig you haven't used before and when you go back through *Launchpad* or *Choose a different rig*; the profile screen still shows when the rig has no profile yet or can't be reached. (ALP-4890)
- **Simple Mode: Focus results, Bahtinov and guide focus; Guided Run.** Focus shows the Smart Focus result as the full UI does (headline, HFR, best position / stars / fit R², the V-curve, *Measured stars*), picks Auto / Manual at the top of its panel, and Manual is the Bahtinov helper; *Main / Guide* focuses the guide camera too. Autopilot is now **Guided Run** (pt-BR *Sessão guiada*) and puts the plan first: Plan → Focus → Polar align, the last step's *Done · Start imaging* starts the queue, and with nothing queued it goes back to the plan. Polar align shows big arrows beside a big bullseye. Settings › Rig shows the guide scope's focal length and the guide camera's pixel size.
- **The profile's site goes into the mount.** On connect, and whenever the profile's site changes, the daemon writes its latitude, longitude and elevation into the mount over Alpaca, so every Alpaca client reads Ara's site from the mount. A site another client writes to the mount is put back when Ara's site changes or the mount reconnects. Other profile saves don't touch the mount; a push waits for a slew to end; an elevation of 0 is treated as unset and leaves the mount's own. (#1485)
- **Polar alignment fills in the guide optics.** A profile with the guide focal length or pixel size unset refused every polar-align solve; on guider connect the daemon now reads the guide camera's pixel size from the guider and works out the focal length from the guider's pixel scale (unbinned, so a binned guide camera reads right), and keeps both in the profile. Values already set stay.
- **Emergency Stop also switches the camera's cooler off.** It used to leave the cooler running; the result now says "camera cooler off", and a cooler that refused is called out. In Simple Mode, a stop you pressed on that device no longer sounds the full-screen safety alarm (its summary pill says what happened); stops from elsewhere and unsafe conditions still do.
- **Emergency Stop confirms by holding.** The status-bar button now takes a 2 s press-and-hold ("Hold to confirm"); letting go early sends nothing. Keyboard and screen-reader users still get the "Stop everything now?" dialog.
- **Imaging runs cool the camera while they get ready.** The cooler starts as soon as a run starts, and the run unparks, slews, focuses and centres while it cools; each target waits for the sensor just before its first frame. With autofocus at start, each target now slews, focuses near the target, then does its go-to: centring on sharp stars when Settings → Plate Solving → "Center target after slew" is on (the default), Center and Rotate when a framing angle is set, a plain slew when the setting is off. Simple Mode always centres. (A solve on an out-of-focus field fails.)
- **Run steps read in plain words.** "Slewing to NGC 7000", "Centring on NGC 7000", "Focusing", "Waiting until 21:47" instead of instruction names; a failed plate solve's retry reads "No plate solve, trying again in 01:15".
- **Mount GoTo switches tracking on first** when it was off.
- **Phones get a phone layout.** On a window narrower than 600 px (a phone in portrait) the tabs move to a bottom bar and the device buttons stand in a column down the left edge, instead of a side rail plus a top bar that doesn't fit. Search, night mode and Settings stay at the top right. Wider windows (iPad, desktop, a phone in landscape) keep the side rail and top bar; wherever the named device buttons don't all fit (a phone in landscape, an iPad in portrait, a narrowed desktop window) they show icons only, so none is pushed off screen. The margins around a phone's notch, status bar and home indicator (an iPad's too) are painted in the bars' colour instead of left black, and the device column starts at the top. A landscape iPhone keeps a margin only on the Dynamic Island side (iOS reserves both) and uses the other edge.
- **Settings move to the top bar, and the guider is set up like every other device.** Options is renamed **Settings** and opens from a gear in the top bar; the left rail keeps the night's workflow: **Planning**, **Checklist** (was Setup; its "Tonight" header is gone), **Sequence** (was Run), **Live**. The top-bar device buttons are evenly spaced, named in full and put the most used first (Camera, Mount, Guider, Focuser, then Filter Wheel, Rotator, Flat Panel, Switch, Weather, Safety, Dome; icons only on a phone-width window), with new Mount (telescope) and Filter Wheel icons. A device that is connected and working (camera exposing, mount slewing, focuser moving) now blinks its dot green instead of showing amber, which is kept for states that need a look. They open each device's Settings page, so the Settings sidebar no longer repeats an Equipment group (⌘K still finds every device setting). The Guider button now opens its Settings page instead of a popup: the page starts with the same connection card as the mount and camera, and its Calibration section holds the dark-library and defect-map controls that used to open in a second popup. Guider settings save as soon as they change, like the other device pages, instead of through a Save button. The guider *Profile* is a picker instead of a free-text field (which nothing read): **Automatic** keeps the guider profile Ara names after the active Ara profile (shown in the picker, e.g. *Automatic (Skywatcher 72ED)*), or pick one of the guider's own profiles, listed while it is connected, to select it on connect. On macOS the app is now named **OpenAstro Ara** in Applications, Launchpad and Finder (was `openastroara`; settings and saved servers carry over). On the wire, the guider state carries `profiles` (`[{id, name}]`) and the guider settings take `phd2_profile_id` (null = Automatic).
- **Each frame skips camera settings it already has.** Before every exposure Ara wrote binning, gain, offset and the subframe again; on AlpacaBridge a binning or subframe write takes ~47 ms (the camera SDK reconfigures) while a read takes ~1 ms. Ara now reads each setting and writes only the ones that differ, checking the camera itself so a bridge restart or another program's change is still caught. On a CM4 with the ASI2600MM the settings step went from ~0.3 s to ~0.03 s, and 1 s darks from 3.30 to 3.08 s per frame (FITS) and 3.36 to 3.11 s (XISF).
- **Set Switch Value picks the switch and port by name (#1157).** The sequence editor lists the connected switches and their writable ports instead of raw numbers, using the same rule the daemon uses at run time (connected switches only; a number two connected switches share is marked ambiguous). With no switch known the number fields stay; with the picked switch not connected the port stays a number field. Saved sequences are unchanged.
- **Sequence frames are saved in the background.** A sequence's next exposure now starts as soon as a frame is downloaded, while that frame is written and catalogued (NINA's async save). On a CM4 with the ASI2600MM each frame cycle is about 0.35 s shorter: 1 s darks went from 3.6 to 3.24 s per frame as FITS and from 3.7 to 3.34 s as XISF; 5 s darks from 7.5 to 7.2 s. At most two frames wait in memory (three only when a save fails during the next exposure); a third waits for the first free slot. A frame that can't be saved is kept and retried before the next exposure, and if the drive still refuses it the run pauses awaiting you, as a missing drive does; Resume saves the held frames, so nothing is lost when the drive comes back. A run waits for its last frames before it reports itself finished (up to 2 min; 20 s for a stopped or aborted run, so a shutdown fits systemd's stop timeout; frames dropped even after that are still reported), and the storage drive can't be switched, checked or ejected (nor the catalog rebuilt) while a frame is still being saved. Take One and other one-off captures still save before they return.
- **Panel flats aim at a share of the camera's own range (#1432).** `FlatPanelFlats` now targets `flat_target_percent` (default 50%) of the camera's MaxADU, measured as the median of the frame's central area, and its `TargetAdu` and `Brightness` default to 0 = automatic. A stored plan that left those fields out (relying on the old 30000 ADU / brightness 50 defaults) now runs automatic; plans that store the values keep them. `post_flat_park_mount` defaults to off, and the Calibration dialog asks about parking each run. Deleting frames from the library always deletes their files (previews, thumbnail and histogram cache too), and runs that saved no frames no longer appear as "Untitled". Bias and darks no longer record the filter the wheel happened to be on.
- **Deleting a profile asks about its OpenAstro Guider profile (§63.4).** The "Delete profile?" dialog (launch screen and Settings → Profiles) now offers *Also delete its OpenAstro Guider profile "<name>"*, on by default, with the note that the guide calibration and dark library go with it. The box is off by default when another profile with the same name shares that guider profile (the survivor needs it), hidden when the guider has no such profile, and annotated when the delete will be queued: *It will be deleted the next time the guider connects* with no guider connected, or the guider's state (*The guider is guiding. It will be deleted once guiding stops*) while it is busy. After Delete a snackbar says what happened: *Guider profile deleted*, *Guider profile will be deleted when the guider is free*, or the guider's refusal. A queued delete is kept on disk and runs on the next guider connect (before the connect re-selects a twin) or the first idle moment, and a queued name that a recreated profile maps to again is dropped, not deleted. On the wire, `DELETE /profiles/{id}` takes `?guider_profile=keep|delete` (default keep, so an older client never deletes guider data unasked) and `?dark_library=keep|delete`, answers 200 with `{guider_profile: deleted|queued|kept|not_found|failed, reason?}` instead of 204, and `GET /profiles/{id}/guider-twin` is the preview behind the dialog.
- **D80 is no longer the default star database.** Settings → Sky data recommends the ladder's pick for the profile's field of view (D05 for a typical refractor) rather than the 1.3 GB D80, which is now the narrow-field choice (below 0.5°). The solver's own preference order follows the same bands; with several databases installed and the profile's optics unset, a solve now names D05 (the general pick) rather than D80, and Settings → Sky data marks nothing Recommended until the optics are set.
- **Dark-library status is one query, not one per combination (#1185).** The build status and the reuse check used to run a `COUNT(*)` per exposure × gain × temperature combination on every poll; they now read one grouped query and match in memory, with the same any-temperature rule for an ambient combination.
- **The plate solver ships with the daemon and uses every core (#1136).** The `.deb` and the Docker image now carry their own `astap_cli` at `/opt/openastroara/astap_cli`: Han Kleijn's ASTAP v2026.11.01 command-line solver (multi-core spiral search, better detection of faint stars, a refit that drops bad quads) with an OpenAstro patch that also spreads the FITS load, the binning and the star detection over every core (git submodule `third_party/astap`, open-astro/astap branch `ara`, MPL-2.0). On the CM4 rig (4 cores, 26 MP frame, D80) a hinted solve takes 0.63 s and a whole-sky solve 2.7 s, against 1.6 s and 3.7 s for Han's own v2026.11.01 build (and 12 s whole-sky for the older single-core stock binary), with the same answer as Han's own build at any thread count; frames with very few stars solve where older solvers gave up (in a dimmed-frame test at 0.15 % of the original signal it finds 15 stars and solves, an earlier fork found 8 and failed). `-threads n` or `ASTAP_THREADS` caps the cores; the star-database block cache defaults to 16 MB per thread (32–256 MB, `ASTAP_TILE_CACHE_MB` overrides it). An error in a worker thread is passed back and fails the solve instead of being swallowed, and a star-database tile that can't be read fails the solve rather than being read as a shorter tile. The `astap-cli` apt dependency is gone, and a profile still pointing at a stock binary (`/usr/bin/astap_cli`, `/usr/bin/astap` or `/opt/astap/astap_cli`) is moved to the bundled one on the next load, including `/usr/bin/astap` from the ASTAP GUI package (which earlier releases left alone); a solver path of your own stays. The star database downloads from Settings → Sky data (see **Added** above).
- **Plate solves are tuned per frame from the rig's geometry, and a failed hint no longer jumps straight to a whole-sky search (#1136).** The solver's downsample factor now defaults to **automatic** for a new profile (a profile that already stores 1–8 keeps it; set 0 in Settings → Imaging → Plate Solving to switch): the daemon picks it per solve from the image scale (focal length ÷ pixel size, with the reducer and the frame's binning folded in) so a RedCat on a small sensor solves at full resolution, the same lens on a 26 MP sensor at 2× and a C11 at 4× (the wizard no longer seeds a number; 1–8 in Settings → Imaging → Plate Solving still override). A hinted solve that fails is now retried in stages before the blind fallback, cheapest first: the last good solve of the session when it lies outside the hinted radius (a mount that lost sync is usually close to where it last solved), the same hint with the image scale searched by ASTAP (`-fov 0`, for a profile whose optics are wrong), then 30° and 90°, and only then the whole sky; polar alignment keeps its fail-fast single solve, and a stage that fails no longer posts an error notice of its own (one notice when the whole solve fails). A frame over 3000 px high is binned at least 2× whatever its scale (ASTAP's star detection is the slow part on a 26 MP frame). On the CM4 rig (RedCat 448 mm, 26 MP) a hinted solve of a catalogued light takes 2.3 s and a hint 100° off recovers in 7 s. The profile's **Timeout** now reaches the solver (it was stored and never read; every solve had a 10-minute cap) and scales with the stage (×2 up to 90°, ×5 blind). A manual solve (the one the user triggers on a catalogued frame) whose pixel scale disagrees with the profile by more than 10% writes the sky-measured focal length back to Options → Imaging → Optics (the reducer entry stays; a change beyond 3× is reported, not learned) and says so; the frame's own binning (`XBINNING`) sets the solve scale, and the unattended solves (center after drift, centering, rotation) never touch the profile. The frame the solver reads is written to RAM (`/dev/shm`) when the host has it, and every solve logs its timing split (write frame / solver / exit code / radius) so a slow night can be read off the daemon log.
- **A relaunched client picks up the run in progress.** With no sequence selected (a fresh launch, or a relaunch while the daemon is mid-run), the Run tab adopts the daemon's active run: the running or paused sequence is selected and loaded, so its band, Resume and Abort are there. Rig night 2026-10-18: the client was relaunched with a run paused awaiting the user, the Run tab came up empty, and the only way to resume was the API over ssh while the ten-minute unattended-shutdown countdown ran.
- **A dither waits out a brief star loss and restarts guiding itself before asking for help.** A guide star lost for a frame or two (a cloud wisp, a seeing dip) used to refuse the dither at once and park the run awaiting the user, although the guider had the star back seconds later; the dither now waits up to 20 s for it. A guider that is stopped altogether (a slew with stop-guiding-when-slewing on, a star lost for longer, or one you stopped by hand mid-run) is restarted by Ara, the way an ASIAIR carries on: the guider picks a star, guides on its stored calibration (calibrating first when it has none) and settles, then the dither goes ahead; an open Ara polar-alignment session ends when guiding restarts, as it does for any Start Guiding. A guider that is calibrating or deliberately paused is never restarted: the run parks with that reason. The run is parked only when that restart fails (with the guider's own reason), and Resume restarts guiding itself instead of needing a manual star pick and Guide first. Rig night 2026-10-18: a two-frame "No star found" and a Planning GoTo each parked the run, and every Resume parked it again within 2 ms.
- **Backlash compensation needs a pulse width to turn on.** Ara used to send the guider an enable with no pulse width when the profile had backlash on and the pulse field empty; the guider range-checked the pulse it already held (0) against its floor (20) and refused the whole group on every settings push, with nothing to show for it in the client (rig night 2026-10-18, "Floor must be in [20, 0 (PulseWidth)]", "applied 10 of 11"). Guider settings → More… now says so by the fields before Apply, the profile write refuses the combination, and a profile saved before this rule skips the backlash group instead of poisoning the push (logged with what to do).
- **The Guiding Assistant no longer looks like a guided run.** PHD2 reports "Guiding" for the whole assistant run with corrections off. Ara now reports it as `assistant` on the wire ("Guiding Assistant" in the strip, chip and Run tab), starts no polar-alignment residual from its uncorrected drift, and keeps the lost-star watch out of it. The dialog's text says what to expect: the drift phase takes the chosen time, and the backlash test that follows runs until the backlash is measured (ten minutes on a mount with a lot of it; the EQM-35 Pro has 11.4 s).
- **A manual GoTo during a run asks first.** A slew sent while a sequence run is in progress stops guiding (the guider's stop-guiding-when-slewing) and parks the run awaiting you; on 2026-10-18 a Planning GoTo mid-dither was accepted without a word. The daemon now refuses such a slew with 409 `run_in_progress` and the reason, and the client asks ("A run is in progress … Slew anyway?"); a yes repeats the slew with `force: true`. A sync never moves the mount and is never refused.
- **A swapped guide camera is re-pinned instead of refused (#1362).** The #1308 pin check still refuses a guide camera that moved to another device number and a slot that holds the main imaging camera; a slot whose picked camera is gone and a different camera answers is a swap, so the push goes ahead, the connect re-pins the new camera's id, re-reads its pixel size and tells the user.
- **The astrometry natives come from maintained upstreams (#1386).** The daemon's fundamental-astronomy and positional-astronomy routines are now built from [ERFA](https://github.com/liberfa/erfa) 2.0.1 (the BSD fork of IAU SOFA, 2023 release) and [SuperNOVAS](https://github.com/Smithsonian/SuperNOVAS) 1.8.0-rc2 (the maintained fork of NOVAS C 3.1), pulled in as git submodules under `third_party/` and bumped by Dependabot, instead of the SOFA 2020 and NOVAS 3.1 copies that had been vendored since the N.I.N.A. port. The libraries are `liberfa` and `libsupernovas`; the P/Invoke structs follow SuperNOVAS's layout (a size test pins them) and SuperNOVAS's legacy JPL ephemeris reader placed the Sun 14° off (`remainder()` for `fmod()`, present since its v0.9); Ara reported and fixed it upstream ([Sigmyne/SuperNOVAS#393](https://github.com/Sigmyne/SuperNOVAS/issues/393), merged the same day) and pins the submodule past the fix, so no build-time patch is needed. Clone with `--recurse-submodules` (or run `git submodule update --init` once); a build on an empty `third_party/` says so. Dependabot also now watches the .NET SDK pin and the Android Gradle plugins.

### Removed
- **The N.I.N.A.-era RAW, TIFF and bitmap image stubs (#1147).** Ara never decodes a RAW file: DSLRs reach it through AlpacaBridge's gPhoto driver, which decodes RAW with libraw and serves an ordinary Alpaca image array. The daemon saves FITS or XISF only. The placeholders that threw pending libraw or OpenCvSharp4 are gone (`RAWExposureData`, the RAW converter camera setting, the DSLR EXIF temperature rename, `SaveTiff`, `FromBitmapSource`). A save to any other file type is refused with `NotSupportedException` naming the type.
- **Accord.NET is gone (#1386, part 3 of 3; closes the epic).** The vendored `Accord.Imaging/` source tree (7 MB, LGPL) was referenced by the image project and used by nothing: star detection and HFR have been Ara's own since the port. The three remaining Accord.Math / Accord.Statistics calls are replaced in kind: the dome-geometry matrices by `System.Numerics` (checked against the Accord build on 200,000 random mount configurations, max 0.006° of float rounding), the custom-horizon lookup by a twelve-line piece-wise linear interpolation with the same edge behaviour, and the direct guider's normally distributed dither distance by Box-Muller. No archived or LGPL package remains in the licence list, and the analyzer gate no longer needs an exemption.
- **The N.I.N.A.-era dead weight is gone (#1386, part 2 of 3).** `System.Data.SqlClient` (eight projects referenced it; Ara never talks to SQL Server), the unreferenced `System.Data.SQLite`, `Microsoft.VisualBasic`, `System.Runtime.Caching` and .NET Framework reference-assembly pins, the MEF plugin attributes on every sequencer item, trigger and condition (`System.ComponentModel.Composition`; Ara has no plugin loader), `CommunityToolkit.Mvvm` (its generated properties are now written out) and `OxyPlot.Core` (the altitude and twilight series are plain `DataPoint` records on the same day-number axis, so the wire is unchanged) are removed, along with the `StarDataImport/` tool, the two unused ASCOM COM-interop DLLs in `T4References/`, and the eight .NET Framework `App.config` files (Entity Framework 6 provider sections, binding redirects and N.I.N.A. user-settings blocks that nothing reads on .NET 10). The licence list no longer carries them.

### Security
- **API hardening (#1194).** While another client holds the control slot, a command that carries the session id of a client that was taken over is refused with 409 until that client re-claims the slot; with the slot free, and for requests without a session header, nothing changes. The daemon serves at most 16 WebSocket subscribers at once and answers the next with 503 and a retry hint instead of running out of memory to a reconnect storm. Frame downloads, previews, exports and deletes only ever touch files under the capture roots (the save directory, the storage drive, the daemon's fallback folder); a catalog row pointing anywhere else is treated as a missing file and logged.
