### Breaking changes
- **Polar Align's motor does not turn a mount until you confirm its clearance** (#2068): the first motor run on each mount asks you to check with the hand controller how far the counterweight can turn up from counterweight-down before the counterweight, the tube or a cable touches the pier or the tripod, and to confirm it (**Confirm clearance…** on the Polar Align card, Full UI and Simple Mode, or Settings › Imaging › Polar align). Until then every motor start (Start, Check, Rough first) from any client is refused with `polar-align-clearance-not-confirmed`, so an existing setup that changes nothing can no longer start a motor run. A **Turn RA by hand** start, which moves nothing, still goes ahead: the clearance check is a warning for it, Start stays on, and its confirm step offers Turn RA by hand alone. A confirmation is for one limit: changing the counterweight limit needs a new confirmation (the rig clears one that does not name the new limit), and **Take back** (in the clearance dialog, or in Settings › Imaging › Polar align) withdraws it. The confirmation and the counterweight limit (60° unless you set it, kept between 10° and 75°) are kept per mount, by its Alpaca identity, in each profile's polar-align section (`mount_clearance`, with `confirmed_max_cw_angle_deg`); a profile you share never carries them. An app from before this update that saves the polar-align settings keeps every mount's confirmation.

### Added (polar alignment)
- **Pre-flight checks on the Polar Align Start card** (#2068): before you tap Start, the card lists every check the rig makes, each passed, a note, failing or not checked yet: the mount connected and not parked, the site latitude, the mount's clock, the mount's position trusted, this mount's clearance, and where the scope points (the start's plan from a fresh reading), with a note to set the mount's own limits in its hand controller. Start (and Check) stays off while a check fails, in the Full UI and in Simple Mode, and the rig refuses a start on the first check that fails, so the list and the start never disagree. The card shows the list for a Turn RA by hand start, where an unconfirmed clearance is a warning, and Start stays on while the list loads or cannot be read (the rig's own refusals stand). The checks a later update adds (mount type, RA motor control, the AlpacaBridge motion-safety marker, pier side, the start pose, the counterweight angle and the turn step against the limit) are listed as not checked yet and never stop a start. `GET /polaralign/start-plan` now refuses on the mount's clock too, as Start does, and waits for the clock push that follows a connect first, so a Start tapped right after connecting still goes ahead. The list reads itself again when the mount connects, parks, unparks or ends a slew, when the polar-align or site settings change, and a few seconds after a failing clock check, so Start comes back on with no refresh tap. API: `GET /equipment/polaralign/preflight` (`ready`, `checks`, `planned`, `mount_key`); `?hand_turn=true` on it and on `start-plan` lists and plans a hand-turn start.
