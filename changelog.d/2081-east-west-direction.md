### Breaking changes
- **Polar Align's first turn goes the way the new Turn direction setting says, not away from the meridian** (Polar Align, #2081): a run that starts from a new pose turns RA east in the northern hemisphere and west in the southern (NINA's default), whatever side of the meridian the tube is on; Ara no longer picks the way from the mount's hour angle, which a wrong mount clock or a false zero made arbitrary. A start west of the meridian in the north now turns east, toward it. Later starts in the same session still turn back toward the first one. **After upgrading:** check the direction the confirm step shows before you tap Move the mount, and if it would cross the meridian from where you point, set Settings › Imaging › Polar align › Turn direction to the other way or point on the other side.
- **A Polar Align start must confirm the motor-direction test** (Polar Align, #2081): while no RA motor direction is saved for the mount's driver, the start plan has `direction_test_deg` 0.5, and `POST /api/v1/equipment/polaralign/start` refuses (`polar-align-unconfirmed`) a motor start that does not send `direction_test: true`. An older app never sends it, so on such a mount it cannot start Polar Align with the motor. **After upgrading:** update the app with the rig.

### Added (polar alignment)
- **Turn direction** (Polar Align, #2081): Settings › Imaging › Polar align › *Turn direction* (`polar_align.east_direction`): Automatic (east in the north, west in the south), East or West, for a run that starts from a new pose. The confirm step names the direction and the turns before anything moves.
- **Saved RA motor direction** (Polar Align, #2081): the first motor run on a mount, and the first after its driver name or version changes, first turns RA 0.5° to learn which way a positive motor speed turns it. The turn uses the same guards as every turn, is shown in the confirm step ("First it turns the mount 0.5° to learn the motor direction") and counts toward the sweep limit. Ara saves the result per profile and driver (`GET /api/v1/equipment/polaralign/motor-direction`). Settings shows it with **Test direction again** (`POST …/motor-direction/retest`), which makes the next start test it again.

### Removed (polar alignment)
- **The mid-move reversal** (Polar Align, #2081): a turn whose reading went 0.5° the wrong way used to be stopped and restarted the other way. Now it stops the motor and the run fails with `turn_wrong_way` ("the mount turned the other way from its saved RA motor direction"). Polar Align never turns the motor back by itself.
