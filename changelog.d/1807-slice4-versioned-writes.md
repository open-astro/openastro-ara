### Breaking changes
- **The rig refuses a settings write that does not say which copy it was made from** (#1807): a write of a profile section (`PUT /api/v1/profile/<section>`) with no `If-Match` version now answers `428 Precondition Required` and writes nothing. An app built before this release sends no version from the setup wizard, a profile saved offline and the recent and saved targets, so on an updated rig the wizard reports sections it could not save and the targets stop syncing (they stay on that device); apps from before the 1.0 betas get the 428 on every settings save. **After upgrading:** update the app on every device together with the rig.

### Changed (Settings)
- **Every settings write sends the version it was loaded with** (#1807): the setup wizard, a profile saved offline and applied on reconnect, and the recent and saved targets now read each profile section with its version and send that version back with the save, as the Settings panels and Simple Mode already do. When another device saved the target list in between, the app reads it again and merges once more; if it is refused again, the targets stay on this device for the next sync. A save the rig refuses for want of a version says "Reload these settings from the rig before saving" and offers Reload. On a rig that sends no version (one older than the 1.0 betas) the app now refuses to save instead of writing over the rig's copy; a profile saved offline that is refused this way, or because a section changed on the rig while it was applied, stays on this device and is tried again on the next connect.
