### Fixed
- **iOS Reduce Motion now stops the client's animations (#1604).** The blinking status dots, Simple Mode pills and transitions, the sequencer and Sky Atlas animations and the album card transition only followed Android's "Remove animations"; they now also hold still with iOS Reduce Motion, including when you switch it while the app is open.
- **The status bar no longer cuts off its launchers (#1553).** On a narrow window or an iPad, Image Library, Calibration, Stats, Launchpad and Run profile wizard shrink to icons (the label becomes the tooltip), then the ones that still do not fit move into a More menu, instead of being clipped under the Backup chip.
- **The Planning search field keeps its width on an iPad in portrait (#1554).** Below 900 pt the Rotate camera and Tonight's Sky buttons shrink to icon-only buttons with tooltips (still filled when their panel is open), so the field no longer collapses to "Se…". Wider windows are unchanged.
- **A Center & Rotate failure names the step and what to check (#1596).** The failure text now says whether the slew (mount, target altitude), the rotation (rotator, rotation tolerance, plate solve) or the centring (plate solve, centring threshold and attempts) failed, instead of one generic "did not converge" line.
- **Polar Align starts from a synced mount that reports Dec past the pole (#1536).** A reading such as Dec 90.9° is folded back over the pole (the same point on the sky) before the seed slew; a refused seed slew says how to recover (slew to about Dec 85°, then start again) instead of the driver's text; and a failed start no longer counts toward the telescope fault escalation that ends in abort-and-park.
- **Polar Align no longer picks the mirror axis near the pole (#1591).** Two seed pointings fit two axis lines that mirror each other; the fit took the one nearer the pole, which for a seed close to the pole could be degrees off while reading as a clean fit. The fit now uses the direction the mount turned to reject the mirror. Every run logs its seed solves, RA turn, fitted axis, live readouts and final error.
- **Autofocus coarse search no longer jumps far past focus on its first move (#1540).** The direction probe moves one step size instead of the whole sweep half-width (falling back to the half-width when the frame is blind that close in, or when one step is lost in noise on a flat wing), and the expansion is capped at a quarter of the focuser's travel.
- **Night Setup ends when Simple Mode closes (#1513).** An autofocus finished in Advanced no longer moves Night Setup on and starts the polar routine with no Night Setup on screen; reopening Simple Mode no longer stops a polar routine Advanced started (#1514).
- **Simple Mode: "Image this" after editing a queued target plans the new pick (#1571),** instead of reopening the sheet on the edited target.
- **Simple Mode: a rail or image tap over an edit with unsaved changes asks first (#1572).** A question pill, "Discard changes to <target>?", offers Keep editing or Discard; an edit with no changes closes as before.
- **Guiding Assistant gets you to a selected star (#1534).** Its window shows looping, star selected and calibrated live, keeps Start disabled until all three hold, and adds Find star (new `POST /api/v1/equipment/guider/live/find_star`) with the guide picture inside the window so another star can be tapped. The guider's raw "no star selected" error reads as a plain message.
- **Multi-star guiding is on by default and reaches the guider when saved (#1592).** An unset profile guides with multi-star (an explicit off is kept); saving the setting, or tapping the Multi-star / Single star chip in the Guide camera window (now a toggle), applies it to a connected guider through new `POST /api/v1/equipment/guider/multi-star/apply`, refused with "stop guiding first" during a guide session.
- **Run status says why (#1596).** A run whose only target was skipped ends with the reason instead of a plain "completed", and a meridian wait or a flip the flight check refused shows its reason while it lasts; the run badge, the completion sheet and Simple Mode's plan pill show it. New `reason_code` / `reason_text` on the run state.
- **Status labels: a slew that centres by the profile default reads "Centring on <target>" (#1573),** and a Cool Camera step that doesn't wait says so: "Cooling the camera to X °C, not waiting" (#1574).
- **No Cool Camera step for a camera that can't hold a set-point (#1577).**
- **Live View follows a server switch (#1587).** The old session is dropped without calling the old server, and the new server is checked for a running loop to adopt.
- **Live View stops itself when no client has fetched a frame for 30 s (#1585),** so an orphaned loop (app killed, phone left the LAN) no longer holds the camera until a daemon restart. A live-stack frame fetch counts as a client.
- **`POST /api/v1/equipment/camera/exposure` answers 409 with the reason, not 500, when an exposure is already in progress or the camera is not connected (#1584).**
- **Emergency Stop meets WCAG 2.2 AA 4.5:1 everywhere (#1569).** Every Stop fills with #D32F2F, uses a white label (the app's dark theme had made it black: 4.2:1 on Simple Mode's red) and darkens under the hold sweep.
- **The night-reference-day event fires once per day change (#1568),** not on every 10-minute tick after the first change.
- **The setup wizard's focuser backlash is applied (#1541).** The backlash in/out steps the wizard asks for never reached the daemon; they now travel with the autofocus profile section and are added on a direction reversal (the new direction's backlash, no return leg, NINA's Absolute method), with a backlash the sweep measured taking precedence for out. The autofocus sweep keeps its own approach direction. While a compensated move is still moving the focuser reports `backlash_compensating` (the client treats it as moving), and a move to a travel stop gives back any standing offset, so no move leaves the travel.
- **Settings › Versions shows the ASTAP version without a trailing comma.** ASTAP 2026.11.01 prints "version CLI-2026.11.01, multi-threaded", and Ara read the comma as part of the version.
- **An old autofocus failure no longer comes back on every launch (ALP-4998).** Ara keeps its last autofocus run until it restarts, and Simple Mode read that run on each launch or reconnect as a fresh failure, so its pill returned after × and after a restart. Only a failure that happens while the app is watching posts the pill now.
- **Tonight's Sky "Up now" no longer turns on to an empty list at dusk.** The chip switched itself on at nautical dark (sun 12° down), but a target's dark window only opens at the site's twilight line, astronomical (18° down) by default. For about half an hour every evening the list showed nothing. The chip now waits for the same line the list uses.
- **Stop and Emergency Stop stop a paused guider (ALP-5018).** While PHD2 was paused, the guider's Stop and Emergency Stop were refused and guiding stayed paused; the only way out was the Live View stop. A paused guider is now stopped like one still looping or on its star.
- **A guider Stop the rig doesn't act on says so (ALP-5018).** Simple Mode's Guide shutter flipped back to running without a word when the guider stayed on after a Stop; a pill now names what it is still doing.
- **The Messier and Caldwell lists are complete (#1516).** The bundled catalog lacked M40 (Winnecke 4), M45 (the Pleiades), the Messier number of NGC 5866 (M102), and the Caldwell entries C9 (Cave Nebula), C14 (Double Cluster), C41 (the Hyades) and C99 (the Coalsack). The missing rows come from OpenNGC's addendum, so search finds all 110 Messier and 109 Caldwell objects offline and the Catalogs overlays show them. NGC 884 now folds into NGC 869 as one Double Cluster row.
- **The planetarium's sky-photo downloads stay within their limit on a slow link.** The client fetches at most 6 DSS2 tiles at once and queues the rest. A queued tile used to give up waiting after 40 s and start anyway, so on a slow hotspot with a long queue the tiles at the back all started together, well over the limit. A queued tile now waits its turn; every download still has its own connect, first-byte and body deadlines, and once the survey is unreachable the queue empties straight away.
- **The iPhone and iPad find the same rigs as the Mac.** iOS refuses raw multicast to apps without a special Apple entitlement, so the iOS app only swept its own /24 subnet and never saw a rig on another network (another VLAN whose mDNS the router reflects), while the Mac listed it; it then also claimed iOS was blocking local network access. iOS now browses through Apple's own Bonjour API, which needs only the Local Network permission and sees what the system sees, and resolves each rig to its IP address. The subnet sweep still follows when the browse finds nothing. The connect screen also rescans when you pull the list down, as well as from ⟳.
- **⌘K (Ctrl+K) opens the command palette again (§61).** The night-mode hotkey wrapper at the app root took keyboard focus before the main window appeared, so the window's own shortcut never saw the key and ⌘K did nothing until you clicked into a text field. The main window now takes focus when it opens; ⌘N / Ctrl+N for night mode still works from anywhere.
- **Polar align stays ticked on the Checklist after you leave the step and come back.** Opening the polar-align panel re-reads the routine from the server, and that read carries the error but not its green/yellow/red zone, so the zone was cleared and the step went back to unticked. The zone is now worked out from the error with the server's own thresholds.
- **A device's busy status no longer freezes.** While a device is busy (exposing, slewing, moving) the client re-reads it every 1.5 s, but only for about a minute; after that it stopped reading altogether, so an exposure longer than that, or a rig restarted mid-exposure, left the Camera chip showing "exposing" until the app was restarted. A device still connected after that minute is now re-read every 15 s.
- **An autofocus sweep wider than the focuser's travel says so instead of sweeping (#1139).** With ±steps × step size larger than the focuser's whole travel, the top probes were sent past its maximum position. The sweep now fails at once with "the sweep (±4 × 100 = 800 steps) is wider than the focuser's travel" and the fix (a smaller step size or fewer steps).
- **A flat panel is connected once at boot (#1157).** A panel remembered once as a flat device and once as a cover calibrator was two remembered devices, so boot and Reconnect connected the panel twice; picking or relocating a panel now replaces the other entry, and a file from an older version connects the panel it last used.
- **Smart Focus no longer lands short after an upward move (#1139).** Its predicted move, the trim and the reversal went straight up, so a focuser with backlash stopped short of the position it reported (about 48 steps on the CM4's ZWO EAF). They now land from above like every calibration sample, and every overshoot clears 1.5× the backlash the calibration measured (one sweep step at least; a 50-step default step was a near miss against those 48).
- **Settings → Storage's file format and compression now reach disk (#1148).** Every frame was written as an uncompressed `.fits` whatever File format, Compression and "Compress darks and bias" said. Choosing XISF now writes `.xisf` frames carrying the same header keywords as FITS (plus the XISF properties PixInsight reads natively), and the library, previews, plate-solve hints and the catalog scan read them like any FITS frame. XISF compression is lossless Zstandard (level 1, two threads) with byte shuffling: a 52 MB frame is written in about 0.5 s on a CM4 and comes out at 22.5 MB (plain FITS: 0.23 s, 52 MB). Switching a profile to XISF compresses by default; Storage → Compression → Off turns it off; "Compress darks and bias" compresses XISF darks and biases even when compression is off. FITS is always written uncompressed. The FITS + RICE and FITS + gzip formats are removed because PixInsight cannot open tile-compressed FITS: a profile that used them writes plain FITS, and the old RICE/gzip compression choices read as Zstandard. The XISF writer no longer offers zlib (about 55 s per frame on a CM4); zlib-compressed XISF from other software still opens.
- **A NaN rotator angle no longer costs the frame, and a format switch never reuses a name (#1148).** A rotator that reported NaN made the frame write fail; that card is now left out the way a NaN weather reading already was. After switching between FITS and XISF, a frame whose name matched an existing frame in the other format (`Light.fits` beside `Light.xisf`) shared its thumbnail and previews; it now gets the " (2)" suffix. Storage → File format's help names the stackers that need FITS (Astro Pixel Processor, DeepSkyStacker, StackingWizard).
- **The mount settles after a slew before the next frame (#1445).** A slew ended the moment the mount stopped reporting Slewing, so an autofocus run straight after a goto took its first frames in the same second: on 2026-10-23 those frames read far worse than focus really was, the coarse search walked away from a focus that was already set, and the run took 8 minutes and three sweeps to get back. Every slew Ara drives itself (a sequence's Slew step, centring, polar alignment's seed slew) now waits the profile's telescope settle time, 5 s by default, after the mount arrives; the meridian flip keeps its own settle, and a goto from the Mount panel is unchanged. Each autofocus coarse probe now also logs the full-resolution HFR and star count beside its binned reading, so a run that is led astray by bad frames shows it in the log.
- **Dec guiding follows the Dec guide mode Ara shows (#1448).** Ara treated its default Auto as "not set" and never sent it, so once the guider's own profile held North (the Guiding Assistant's Apply puts it there for a mount with large backlash), the guider kept guiding North only while Ara showed Auto, and Dec drift that needed a South pulse went uncorrected all night. Ara now sends its Dec mode on every connect and Tune Guiding, Auto included, so a North or South set directly in the guider is replaced by Ara's setting. Guiding Assistant Apply now also saves what the guider took (exposure, minimum moves, Dec mode, Dec algorithm, backlash compensation) into Ara's guider settings, so Ara shows what the guider runs and its next push keeps it.
- **A sequence's Slew step centres on its target when "Center target after slew" is on (#1446).** The setting (Settings → Plate Solving, on by default) said a slew would plate-solve and re-slew until on target, but the sequence's Slew step only sent a goto, so a mount whose pointing model was off imaged the wrong field: on 2026-10-23 a run to the Helix Nebula landed 5° away in RA while the mount reported the target. With the setting on, the step now slews, plate-solves, syncs and re-slews through the same centring as Center and Rotate, and fails the step if the mount refuses the slew or centring does not converge. With the setting off it slews blind as before. A hand-built or NINA-imported sequence that follows its Slew with its own Center or Center and Rotate step now centres twice with the setting on; drop one of the two or turn the setting off.
- **A device you connect shows its details straight away.** After a connect (including a Remove and connect again) the card could sit for up to 15 s without its sensor, readings or ports: the daemon announced *connected* before it had read the device, and the client only picked the details up on its next 15 s check. Every device type now announces again once the details are read, and the client no longer misses an announcement that arrives while it is mid-read. WebSocket consumers: a connect now emits a second `equipment.state_changed` with `state: "connected"` and `details_ready: true`; it is not a reconnect, and `equipment.connected` still fires once.
- **A local AlpacaBridge is addressed as localhost, whatever network the box is on.** Ara remembered each device under the address the bridge was found at — the hotspot's, a field router's, the home LAN's — so moving the box between networks (or plugging into a different NIC or router) left devices saved under an address it no longer had, and each one waited out the 60 s Alpaca timeout at boot and showed "offline" while the bridge sat on the same board (the CM4 on 2026-10-22: six devices saved under the field router's 192.168.8.118). A device whose Alpaca server is this machine is now dialled and remembered as `localhost` (the connect routes, the remembered-selection file on save and on load, and the boot / manual reconnect). A device saved under an address this box no longer has is found on its own bridge by type, number and UniqueID, connected through `localhost` and re-saved, so an existing install heals itself on its first boot after the upgrade (a device whose UniqueID the bridge has since renamed — the ZWO dew heater under AlpacaBridge 5 — is picked once more by hand). A device on another machine keeps its address, even when that machine shares this one's host name.
- **Deleted frames stay deleted, whichever app deleted them (#1437).** `POST /api/v1/frames/bulk/delete` now always removes the FITS file and its previews, thumbnail and histogram cache. A request with `delete_from_disk: false` used to drop only the catalog entry, and the server's startup scan found the file and put the frame back. The field is now optional and ignored.
- **A camera that stops responding during autofocus, a plate solve or the rotation readout says what to do (#1436).** Outside a run there is nothing to Resume, so those errors now end "Check its USB cable and power, then try again." The Plan screen's rotation readout says *Camera unavailable* instead of blaming the sky with "The field would not solve".
- **Bias and darks after sky flats always wait for the lens cap (#1435).** A calibration run that shot twilight flats and then bias or darks could skip the lens-cap pause when the request didn't ask for it, so the "darks" were taken with the scope open to the sky. Those runs now always open the panel cover (if any) and wait for you to cap the scope before the bias and darks.
- **Devices that AlpacaBridge has to search for connect on the first try (AB #1452).** A serial device on *auto* (Gemini flat panel or power hub) or an iOptron on the network can take 8–13 s to answer while the bridge probes ports or scans the network. Ara gave up after 5 s, sent a second connect that restarted the search, and the fault recovery retried again, so these devices sat on *Connecting…* for minutes. A connect now waits up to 60 s with a single request, and the recovery steps keep waiting while a connect is still in progress. Checking that a connected device is still there stays quick. A device that never answers now takes up to 60 s to show *Error*, and each recovery attempt on it waits as long.
- **A focuser or rotator chip no longer stays amber after the device is back (#1430).** A *degraded* warning raised before an Ara server restart was never cleared, so the chip stayed amber on a healthy device. Reconnecting the device now clears it.
- **Opening a frame in the Image Library no longer times out while the grid loads.** A drive whose thumbnail and preview caches are missing (a copied drive, or after *Clean cache*) makes the grid render every tile, and a frame you opened waited behind all of them: 95–108 s on a CM4, past the client's 60 s limit ("your rig took too long"). Previews now take the next free render slot ahead of any queued thumbnail, and a thumbnail is shrunk before it is stretched, as the preview already was, instead of stretching all 26 MP for a 320 px tile. On the CM4 with 50 uncached frames, a preview opened mid-grid comes back in 2.6 s instead of 108 s, and the grid fills in 43 s instead of 113 s.
- **Choosing a second disk switches the store to it (#1427).** With two drives plugged in, *Use Disk* on the second one said it worked but frames kept going to the first until a reboot. The previous drive is now unmounted first (a busy one refuses with nothing changed), and a switch that fails puts the previous drive back. *Check disk* reports repairs again (every repair read "clean"), and checking a drive that is not the store no longer makes it the store.
- **The guider profile of a deleted profile was never actually deleted (§63.4).** The old silent cleanup only ran with the guider connected, and the guider refuses `delete_profile` while any of its equipment is connected — which, with the guider connected, it nearly always is — so the twin and its dark library were left orphaned every time, with a warning in the log and nothing in the app. The delete now releases the guider's equipment, deletes, re-selects the active profile's twin and reconnects, the way a rename already did, and never interrupts a guiding, calibrating or looping guider (the delete waits instead).
- **A solver database is never orphaned by an index-path change, and an unwritable path is refused up front (#1136).** The Data Manager records where each ASTAP database was installed; after Options → Plate solving → index path changes, the earlier copy stays listed (with its path shown under the row), a plain download is still accepted (it lands under the current path, where the solver looks), and *Remove* frees every copy the daemon remembers. A path the daemon cannot write to (outside the service's writable set) is refused before any byte is downloaded, naming the path and the reason, instead of failing deep into a 1.3 GB transfer.
- **Setup → Connect counts all your gear, not just cameras.** The AlpacaBridge check only asked for cameras, so a rig with a mount, focuser and wheel read "2 device(s) advertised, connectivity not verified" in amber. It now scans every Alpaca device type and shows a green "AlpacaBridge found — offering 2 cameras, 1 mount and 1 focuser. Each one is checked when you connect it"; the daemon's manual filter wheel isn't counted, and one type failing no longer hides a reachable bridge. This replaces the 2026-08-10 amber "connectivity not verified" state: a phantom slot (advertised, no hardware) is still never called connected, but the copy now says so instead of the colour.
- **A non-String-keyed instruction default fails loudly in a release build (#1185, §38).** The sequence editor's default cloner threw a debug-only assertion that a release build stripped, leaving a bare cast error; it now throws a typed `ArgumentError` in every build mode.
- **Guiding Assistant → Accept works with openastro-guider 2.1.0.** The guider answers `guiding_assistant_apply` with bare names in its array (invalid JSON); Ara's parse failed and the dialog said "Unable to get response from phd2" although the guider had applied every value, so Ara's profile fell out of step with the guider (rig night 2026-10-18, four Accept presses). A reply that fails a strict parse is repaired by quoting the bare names and parsed again; the rows now show · applied and the profile follows.
- **A tapped guide star reads "Star selected" with its SNR, and the Multi-star chip shows.** Every looping frame from the guider used to put the live state back to "Looping" after a tap, and the SNR was shown only while guiding, so a tap moved the lock box and nothing else changed (rig night 2026-10-18). The state now stays "Star selected" until the star is lost, deselected, guiding starts or the loop stops, and the chosen star's own detection supplies the SNR and mass. The dialog's Multi-star / Single star chip never showed because openastro-guider 2.1.0's `get_guider_options` has no multi-star flag; Ara now reads it from `get_profile_setup` when the first answer lacks it.
- **The desktop mirror no longer retries frames the rig can never serve.** The backup stream's queue handed out every un-mirrored catalog row, including frames whose file is missing or sits outside the capture roots (a catalog from before the §29 store), and the client fetched them every poll and got 404 each time, with a "Frame file refused" warning in the daemon log per attempt (two frames, every 15 s, all night on 2026-10-18). The queue now applies the download endpoint's own servability test (quietly: the per-poll warning is gone) and leaves those rows out, logging each one once; the skipping happens inside the paging, so a catalog with many such rows still hands out its newer frames instead of an empty page.
- **A daemon restart no longer aborts on a hung weather read.** The dew advisor's stop waited for a check in flight with the host's shutdown token; when a weather read hung past the 30 s budget the cancellation escaped and the old process died with SIGABRT instead of exiting (rig, 2026-10-18 19:21, `systemctl restart` took the full 30 s). The stop now cancels the check first and, if the budget still runs out, logs it and returns.
- **The Run tab says what a run is doing from its first step.** The `sequence.progress` frame carried counts and estimates but not the current instruction's description or target, and the client re-read those only on lifecycle events, so a step that produces no frames left the Run tab on "Run started": on 2026-10-18 the camera cooled for 4 min 40 s with no sign of it. Every progress frame now carries `current_instruction_description` and `current_target_name`, so the band and the ticker show "Cooling camera to -10 °C" (and every later step) as it happens.
- **The guide camera's pixel size and id are re-read when the guider connects (#1362).** After the guider connects, Ara reads the guide camera's `PixelSizeX` and `UniqueID` from its Alpaca server; a changed pixel size replaces the profile's `guide_pixel_size`, an empty `guider_camera_alpaca_unique_id` is filled, and one log line gives the old and new values. A non-empty pinned id that differs from the camera in that slot is never overwritten (the camera moved or was swapped, #1308): the profile stays as it is and one warning is logged. A camera that cannot be read changes nothing and never delays or fails the connect. The new size reaches PHD2 on the next profile push.
- **Guiding Assistant leftovers (#1364).** Start is held while the guider is guiding (a run's or your own) and the headline says to stop guiding first, instead of a Start that only fails; closing and reopening the dialog keeps the **applied** marks and does not re-tick what Accept already wrote; a missing drift figure reads "—" rather than "—/min"; the daemon waits 25 s (not 5 s) for the guider to answer a Start and the client 30 s, so a slow guider no longer shows an error for a run that did begin. Switching servers now clears the guiding graph and seeds it from the new server's history instead of keeping the old one's. The user guide names the Dec guide mode / algorithm suggestion.
- **A fresh checkout's `dotnet test` no longer fails 34 astrometry tests.** The SOFA and NOVAS31 natives are now built from the vendored sources during `dotnet build` on Linux and macOS (once, into `obj/`, rebuilt only when a source changes) and copied next to every binary like the JPL ephemeris, instead of waiting for someone to run `scripts/build-astrometry-natives.sh` by hand into the test directory. A cross-publish (the Pi's linux-arm64 package) is untouched: CI still stages its own arm64 build after publish. A host without a C compiler gets a build warning and the old behaviour.
