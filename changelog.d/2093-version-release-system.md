### Added
- **One version for the whole project, and source-only releases** (#2093): a root `VERSION` file (`X.Y.Z`, or `X.Y.Z~betaN` for a beta) is the one version the daemon build, the app and the README badge carry; `scripts/version.py --check` fails when they disagree. The daemon reports it on `/server/info`, `/server/versions` and mDNS, and the About panel shows it, in the SemVer spelling (`1.0.0-beta.1`). A release is a `vX.Y.Z` or `vX.Y.Z-beta.N` tag, plain-language notes from `docs/releases/<version>.md` and an `openastro-ara-<version>-source.tar.gz` with every submodule and its `.sha256`; no `.deb`, apt package or app binary is published, and users build it from source (`docs/RELEASES.md`, `docs/RUNNING.md`). Betas live on a `stable/X.Y` branch and reach `master` through merge-down PRs. Logs, the daemon's HTTP user agent and the `SWCREATE` header of every saved frame (FITS and XISF) carry the same version: frames now say `OpenAstro Ara <version>` instead of `OpenAstro Ara` or `N.I.N.A. 3.2.0.9001 (x64)`.

### Added (client)
- **The app warns when the daemon is a different release** (#2093): when the daemon's major or minor version differs from the app's, the About panel, the first-run screen and Simple Mode's version rows show a warning ("Server 1.0.2 and app 1.1.0 differ; update both from the same release.") that blocks nothing. A different patch number gets no warning.

### Changed (tooling)
- **Release tooling follows AlpacaBridge** (#2093): `changelog-fragments.py` gains `--bump`, `--is-beta` and `--preview --version`, and `--release` takes `X.Y.Z` only (betas and the old `0.0.1-ara.N` form are refused). New scripts map tags to versions, print a section of the changelog, name CI dev builds, exempt merge-down PRs from the falsified-by gate, close issues fixed on a stable branch and check that each issue has a type, priority and size label. `/bump-release` drives a release.
