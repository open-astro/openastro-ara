### Added
- **§59.9 — autofocus waits out bad sky.** Every autofocus trigger (after-exposures, time, temperature, HFR trend, filter change) now consults the diagnostics state before firing: while an open sky-condition issue says clouds are passing, the aperture is blocked, or dew is forming, the trigger defers — with an in-app notification ("Autofocus deferred — clouds passing. Will run when conditions recover.") posted once per episode — and fires as soon as conditions clear, instead of burning 30 s–5 min of sky time on a sweep that would fail. Non-sky issues (disk space, guider recovery) never defer focusing, and a broken diagnostics read fails open — diagnostics can never freeze autofocus. NINA fires autofocus regardless of conditions; this is deliberate sky-time savings.
- **§59.5 — captured light frames are star-analyzed live.** Every light frame now gets its HFR and star count measured right after capture (off the capture path — the next exposure never waits on a statistic) and written into the frames catalog, so the Image Library's HFR badges fill in seconds after each frame instead of only via a FITS rescan. This also switches on the "Autofocus After HFR Increase" trigger, which was inert without live per-frame HFR data: a rising HFR trend across your recent frames can now fire a refocus mid-sequence. Frames with too few stars for a stable measurement are skipped honestly rather than recorded as noise.
- **§59.5 — the autofocus trigger family.** Sequences can now refocus automatically on the four classic conditions: elapsed time since the last autofocus, focuser-temperature drift, a rising HFR trend, and the first light frame on a newly-selected filter (how per-filter focus offsets are learned under the §59.6 use-current-filter policy). All four appear in the sequence editor's trigger picker, deserialize intact from imported NINA plans, and run the real §59 V-curve sweep when they fire; the daemon keeps a session history of completed autofocus runs (temperature + filter) as their reference point. (The HFR-drift trigger waits on live per-frame HFR analysis, a tracked follow-up; until then it simply never fires.)

### Fixed
- **§58 — a target genuinely at the vernal equinox no longer confuses the meridian flip.** A flip target of exactly RA 0h / Dec 0° was always treated as "never filled in" and silently replaced with wherever the mount pointed. Now that substitution only happens when the mount is pointing somewhere else; with the mount actually on the equinox region, the coordinates are trusted as the real target.
- **§44 — the backup stream handles a server switch and a failed confirmation gracefully.** Switching WILMA to a different server now releases the old server's stream slot and re-claims cleanly on the new one (previously the stale claim self-healed only after a slot-lost round-trip), and a frame that stored + verified but whose confirmation to the daemon failed is confirmed directly on the next pass instead of being downloaded again — no double bandwidth spend on flaky links.
- **Autofocus/dither triggers added in the sequence editor now actually act when they fire.** A trigger built in WILMA shipped an empty action container, so a firing "Autofocus After Exposures" (or "Dither After Exposures") executed nothing, silently. Editor-built triggers now carry their action (Run Autofocus / Dither) exactly like NINA-exported plans do.
