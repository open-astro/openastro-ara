### Breaking changes

- **Polar Align needs your confirmation, and never homes or unparks** (Polar Align, #2048): Polar Align used to send the mount Home before every step and unpark a parked mount. It now starts from where you pointed the mount, refuses a parked mount, and moves only after you confirm. A client that starts it without the confirmation (an older app, a script calling `POST /equipment/polaralign/start`) is refused with `polar-align-unconfirmed`; the start also carries back the plan's `new_origin`. A run that would turn RA more than max(30°, 2 × step + 2°) from where Polar Align first started is refused with `polar-align-sweep-limit` (30° at the default 10° turns). The *Send the mount Home first* setting (`use_home`) is gone; a saved value is ignored. Simple Mode's Preflight no longer starts Polar Align on its own when you reach the step. **After upgrading:** update the app with the rig. Point the tube near the pole, counterweights down, unpark the mount, then start Polar Align and confirm the turn direction it shows.

### Fixed (Polar Align)

- **Polar Align starts like NINA's: no Find Home, no GoTo** (#2048): on RC51 the routine sent the mount Home before each step and took AlpacaBridge's "at Home" as proof of where the mount was; with *Send the mount Home first* off, each later step slewed back to the run's start. Now no step calls Find Home or slews, as NINA's Three Point Polar Alignment, which never homes and starts from where the mount is. With no Home between the steps, each later step turns inside the arc you confirmed: Fine turns back over Rough's arc, and Verify's turns stay inside it too (Rough, Fine, Verify at 10°: 0 → 20° → 0 → 20°). A parked mount is refused ("Mount is parked — unpark it and point near the pole first"), as NINA does; Polar Align never unparks it.
- **Polar Align reads where the mount points from the mount itself** (#2048): the turn direction you confirm, and the arc every later step keeps to, come from a fresh read of the mount. When the mount does not answer (a WiFi hiccup), the start is refused, or the step fails before it turns, or the turn stops and the run fails, instead of using the daemon's last cached position, which after a failed status poll is a (0, 0) placeholder (read from it, a turn could reverse its motor and run the wrong way).

- **Repeated Polar Align runs no longer walk the mount toward the pier** (#2048): with no Home between runs, each Start used to measure from wherever the mount was, so *Adjust again* after *Verify* turned RA 20° further each time. Polar Align now remembers where it first started after the mount connected, turns every later run back toward that start, and refuses a run that would take RA more than max(30°, 2 × step + 2°) from it, 30° at the default 10° turns ("The mount has turned N° from where Polar Align started; slew it back near the pole (counterweights down) and confirm again"). It measures only from changes in the mount's own RA readings, never the mount's clock or its absolute position. Moving the mount some other way, or reconnecting it, makes the next confirmed start the new start; turning tracking on or off between runs can count as such a move. Tracking that stays on or off does not. The confirm step says the turns go back toward the start only when they do.

### Added (Polar Align)

- **A confirm step before the mount moves** (#2048): Start shows "point the tube near the pole, counterweights down", which way RA will turn (east or west, about 10° twice), the most the run turns, and "keep a hand on the mount's power switch", in English and pt-BR. The daemon reads the direction from the mount (`GET /equipment/polaralign/start-plan`) and refuses a start that does not carry it back, or whose direction changed since. Full UI and Simple Mode.
